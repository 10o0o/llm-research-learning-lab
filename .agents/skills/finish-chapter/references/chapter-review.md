# 챕터 회고 작성 틀

대상 산출물은 보관 노트북과 같은 이름의 `.md`다. 아래 구성을 필요에 맞게
짧게 채우고 빈 항목은 제거한다. 별도 frontmatter, 진도 ID, 점수표는 만들지 않는다.
정리일은 실제 작성일이며, 확인되지 않은 학습 시작일·완료일을 추정하지 않는다.

- 제목과 기준 자료: 정확한 강의·판본, 공식 링크, 정리일, 보관본 링크.
- 수행 범위: 강의 따라 구현, 별도 exercises, 보충 실험을 구분한다.
  미완료 요구사항·도움받은 구현을 숨기지 않는다.
- 과정과 확인 결과: 중요한 질문/오류 → 수정 → 결과를 연결한다.
  보관본 셀 번호는 1부터 세고, 덮어써진 내용은 현재 대화에서 확인한
  기록이라고 구분한다. 해석되지 않은 출력은 관찰된 출력으로만 쓴다.
- 이해와 도움: 대표 시도별 첫 작성·답변, API 문서·개념 힌트·과거 코드 도움의
  종류와 시점, 학습자 실행·해석 범위를 구분한다. 자료를 본 실무 구현과 자료를
  닫은 회상·지연 전이는 별도 근거다. 대화 전문이나 모든 질문을 전사하지 않는다.
- 재현·자원 범위: 환경 재구성, 수치 허용 오차 내 실행, 통계적 결과 재현을
  구분한다. 공식 판본·선택 범위·공식 저자원 조정·임의 축소·미검증 hardware를
  밝히며 seed 고정이나 저장 출력만으로 재현 성공을 추정하지 않는다.
- 한계와 다시 볼 부분: 미검증 재실행, stale 출력, 실험 오염, 남은 개념 등
  실제 관련 사항만 적는다. 실습 전체를 다시 시험할 의무를 만들지 않는다.
- 연결: 관련 knowledge, 원본 자료, 실습 위치를 상대/공식 링크로 연결한다.

같은 챕터를 다시 호출하면 기존 회고에 새로 확인된 내용만 병합한다.
원본 노트북 덮어쓰기나 자동 진도 전환을 회고 작성에 포함하지 않는다.
