# 조사 근거에서 학습 경로로의 선택

**상태: 2026-10-19 사용자 승인 설계.** 실제 이행과 학습자 수행은 구별한다. [JD 원문](jd-evidence.md), [교육과정 비교](reference-curricula.md), [기술 동향](trend-evidence.md)의 ID를 사용한다. ID는 정적 출처 참조이며 진도·점수·자동 선택 키가 아니다. 아래 선택은 튜터의 설계 판단이며 원문 기관의 추천이나 채용 보장이 아니다.

## 1. 직무군과 필요한 근거

| 목표군 | 비교 근거 | 이 경로가 준비할 학습 근거 | 별도로 남는 요건 |
| --- | --- | --- | --- |
| 단기 AI 응용/AX 개발·업무 통합 | JD-KR-01·02·05·07, JD-US-01·02·06 | 문제→입출력→AI/데이터/API→평가→운영의 한 흐름, 본인 코드·오류 진단·설명 | 실제 경력 연수·고객 운영·영어·학위 등은 해당 공고와 개인 사실을 별도로 대조 |
| 모델 학습을 포함한 응용 MLE | JD-KR-06 | AX 서비스와 RE-01·해당 모델 학습/평가 비교의 연결 | 이 역할의 직접 학습/운영 요건은 API 앱만으로 충족되지 않음. 목표에 따라 해당 학습 단위를 조기 선택 |
| 장기 모델/후속학습 연구엔지니어 | JD-KR-04, JD-US-03·04 | 데이터·loss·최적화·학습/검증·실험 통제, LM 내부, 모델 행동 비교·연구 보고 | 석사 필수 공고의 학위·대규모 학습·논문 실적은 개인 프로젝트로 대체되지 않음 |
| 장기 추론/시스템 연구엔지니어 | JD-KR-03, JD-US-04·05 | workload를 고정한 품질·수치·지연/처리량·메모리·병목 분석 | 다중 GPU/대규모 운영·kernel 경험은 별도 자원과 직접 수행이 필요 |

처음에는 첫 줄에 집중한다. 연구용 모델 학습을 끝내기 전에도 실제 자기 기여와 공고가 맞으면 지원 자료를 만들 수 있다. 작은 로컬 앱을 기업 운영 경력으로 확대하지 않는다.

## 2. 기본 프로젝트 후보 비교

| 후보 | 직무 연결·평가 가능성 | 제약 | 선택 |
| --- | --- | --- | --- |
| **업무 문의 처리 보조 서비스**: 문의에서 필요한 사실/누락을 정리하고 근거 답변·처리 초안을 제시 | 구조화 출력, 문서/DB/API 연결, 제한된 tool workflow, 사람 확인·회귀·운영을 한 프로젝트에서 비교 가능 | 실제 고객/사내 자료는 쓰지 않음. 공개 권리 확인 자료와 별도 평가 사례가 필요 | **기본안**. 첫 단위는 한 문의의 입력→유용한 구조화 초안까지 작동; 자동 외부 처리·금전 업무는 제외 |
| **사내비를 참고한 문서 Q&A 재구현** | 사용자에게 친숙한 맥락이고 검색/근거 평가에 적합 | 원 프로젝트·도움·팀 기여와 새 작업 분리 필요. 단순 복사 시 새 직접 구현이 아님 | **대체 후보**. 사용자가 선호하면 같은 역량·단위 계약으로 맥락만 바꿈; 원 서비스 변경 없음 |
| **소형 모델·추론 최적화 도구부터 시작** | 모델/시스템 JD에 직접 연결 | 학습/평가·자원 선수가 더 크고 당장 업무 통합 증거를 만들기까지 멀어짐 | 첫 AX 프로젝트로는 제외, RE-01~04에서 사용 |

서비스의 구체 도메인·모델 제공자·데이터셋은 실제 자료 권리·접근·장치·비용을 확인해 준비한다. 이 결정은 튜터 책임이며 학습자에게 또 하나의 긴 기획 시험을 요구하지 않는다. 프로젝트 수를 늘리기보다 AX에서는 하나를 발전시킨다.

## 3. 근거→역량→선택 자료→직접 산출물

단위의 자세한 10개 안내 요소는 [학습 계약](../contracts/learning-contract.md)에 있다. 아래 순서는 취업 우선의 설계 선택이며 공식 기관의 필수 수강 순서가 아니다.

| 단위 | 직무·동향 근거 | 배울 역량 | 사용할 레퍼런스 범위 | 직접 산출물·평가 |
| --- | --- | --- | --- | --- |
| **AX-01 작은 AI 업무 기능** | JD-KR-02·05, JD-US-01·06; TREND-01·05 | Python 요청/응답·구조화 출력·입력 검증·모델 호출, 단순 baseline과 대표 사례 평가 | REF-03 LLM Foundations/앱 출시의 원리, REF-06 Unit1 메시지·LLM/도구 기초 | 한 문의→구조화 초안의 CLI/API, 정상·불완전·범위 밖 사례, 형식/내용 오류, 실제 도움·실행 한계 |
| **AX-02 데이터·검색·근거** | JD-KR-02·07, JD-US-01; TREND-03·04 | 수집/정리·chunk·metadata·sparse/dense 검색·context 구성·근거/기권, 검색과 답변 평가 분리 | REF-03 Augmented Language Models, REF-04 필요한 datasets/tokenizers 설명, Microsoft RAG 설계 자료 | 같은 서비스에 문서/DB 근거 연결. 단순 검색 대비 embedding 또는 hybrid 중 하나 비교, held-out 질의·출처 오류/답변 누락 |
| **AX-03 도구와 제한된 workflow** | JD-KR-05, JD-US-01·02·06; TREND-02·05·08; REF-07의 coverage | API/SQL 도구 계약, 상태·timeout/retry·중복 처리·사람 확인, 고정 workflow와 bounded single-agent 비교 | REF-06 Unit1 tools/action/observation와 Unit2.3 LangGraph 한 framework; Google 자료는 coverage 대조 | 조회 도구 하나+로컬 처리 초안/모의 상태 변경, 실패/복구·승인 전후 확인·step 제한. trace와 실제 최종 상태 대조 |
| **AX-04 서비스 품질과 지원 근거** | JD-KR-01·02·05·07, JD-US-01·06; TREND-01·06·08 | API·저장·테스트·컨테이너/로컬 배포, 관측성·권한·PII 경계·지연/비용, 사용자 설명 | REF-03 UX/LLMOps; REF-08의 Production 구성 참고, REF-09의 문제/코드/평가/설명 연결 | 재현 가능한 서비스, 회귀 사례와 실패 진단, 구성/실행 안내·데모·본인 기여/주장 한계. 실제 외부 배포는 별도 |
| **RE-01 모델 학습과 신뢰할 실험** | JD-KR-04, JD-US-03·04 | tensor/label/logit/loss, autograd·optimizer·train/eval, 일반화·분리·불확실성, gradient/행렬 기초 | REF-01 2026 L1 및 필요한 sequence 설명, REF-04 Ch2~3·5; MML/MIT/ISLP는 공백별 보조 | 작은 신경망 학습·검증 실험 하나. 기존 MLP 근거 활용, 작은 배치 과적합·분리 오류·비교 조건 진단, 직접 training loop·실제 해석 |
| **RE-02 작은 언어모델 하나** | JD-KR-04, JD-US-03·04; REF-02 | tokenizer·embedding·causal attention·Transformer·next-token CE·sampling·checkpoint, 계산/메모리 이해 | REF-02 2026 L1~3·12~14; REF-04 Ch1·6 보조. 기본은 자체 LM 프로젝트; 공식 A1 선택 시 대체 | 제한된 corpus에서 직접 학습/검증하는 작은 decoder LM, 데이터/shape/mask/loss 흐름·생성/재개·오류 설명. 공식 과제 전체 완료와 구별 |
| **RE-03 후속학습·평가 한 비교** | JD-US-03, JD-KR-04; TREND-01 | 기본안: chat template·SFT/PEFT·response loss·data quality·오염/분리·모델 품질/자원 비교 | REF-05 instruction tuning/chat templates/SFT·evaluation, REF-04 Ch10~11, REF-02 L15 설명 | base 대비 SFT 한 비교. 동일 held-out 과업, 변경 요인·고정 조건·오류·비용/메모리·불확실성 해석. 개선 자체는 완료 필수 아님 |
| **RE-04 독립 질문·재현 한 cycle** | JD-US-03·04, JD-KR-03·04 | 질문·논문 독해·가설·baseline·통제·ablation·반복/변동·실패 분석·주장 한계 | REF-02의 평가/데이터·선택 전문화 설명, 실제 읽고 검증한 논문 한 편의 제한된 실험 | 자기 질문 하나의 재현/변형 보고서·실행 근거. 원논문과 로컬 차이·실패/불확실성 포함. 지원 시 실제 요건과 다시 대조 |

**RE-03 대안은 추론/시스템 한 갈래다.** JD-KR-03·JD-US-05와 실제 목표/병목이 더 맞으면 REF-02 L2·5~8·10의 필요한 설명 및 A2 선택 범위를 사용한다. 같은 모델/요청에서 prefill·decode·KV cache·batching 중 한 변수를 바꾸고 수치·품질·지연/처리량·메모리를 비교한다. 학습 profiling과 serving 측정은 구별한다. SFT와 추론 두 갈래를 모두 졸업 조건으로 만들지 않는다. 자원 없는 B200/다중 GPU 결과는 미수행으로 남긴다.

## 4. 사용자의 예시와 유행 기술의 역할

| 예시/기술 | 새 역할 | 선택·복귀 조건 |
| --- | --- | --- |
| 사내비 | 프로젝트 맥락의 대체 후보 | 학습자 선호·자료 권리·새 기여를 확인한 뒤 같은 학습 계약으로 선택 |
| TF-IDF | AX-02 sparse baseline의 **후보 하나** | 단순 키워드/BM25 등과 문제·기존 환경에 맞게 하나 선택; 모두 순차 구현하지 않음 |
| 분류기 | AX의 공통 필수에서 제외한 task-specific 확장 | 실제 routing 오류·라벨·독립 분리·직무 요구가 있고 규칙/LLM보다 비교할 이유가 생길 때 |
| 분류모델 파인튜닝 | AX 공통 필수에서 제외 | 분류 baseline·라벨/평가·자원이 있고 실제 실패를 개선할 가설이 있을 때. RE-03의 생성 LM SFT와 다른 활동 |
| LangChain/LangGraph | 프레임워크 학습은 AX-03 한 개 선택, **기본안 LangGraph** | 상태·도구·사람 확인의 책임을 이해하기 위해 선택. 사용자 예시가 근거가 아니며, API/조건은 수업 전 검증. 별도 LangChain 전 과정은 없음 |
| MCP | 한 도구 연결의 선택 확장 | 외부 도구 표준화나 실제 JD/프로젝트 필요가 확인될 때. 직접 tool contract를 먼저 이해하고 운영 권한 구별 |
| multi-agent·A2A·장기 메모리 플랫폼 | 보류 | 단일 workflow/agent가 해결하지 못한 분해·context·통신 문제가 있고 비교 지표·운영 비용을 제시할 수 있을 때 |
| DPO/RLVR·대규모 사전학습·kernel/분산 구현 | 후속 전문화 후보 | LM·목적함수·reward/데이터·평가와 자원이 갖춰지고 실제 질문이 해당 방법을 요구할 때 |
| ASR/TTS·실시간 streaming | 목표 직무에 따른 응용 확장 | JD-KR-05 같은 음성/실시간 업무를 실제 목표로 선택하면 기본 동작·오류와 상태/연결을 보강. 텍스트 AX 전체의 공통 선행으로 두지 않음 |

## 5. 선수 개념을 배울 시점

| 반드시 먼저 설명할 최소 개념 | 사용할 곳 | 문제 안에서 깊이를 늘리는 조건 |
| --- | --- | --- |
| Python 자료/함수·JSON·HTTP·예외, LLM token/context와 비결정성 | AX-01 요청 처리·검증·평가 | API/파싱·timeout·잘못된 형식이 실제 막힐 때 해당 동작만 보강 |
| 표본 단위·대표 사례·개발/최종 평가·누수·지표·baseline | 첫 AX 평가와 모든 비교 | 반복 출력/사례 중복, 작은 차이 주장 때 변동·신뢰구간·검정의 가정 보강 |
| 벡터·내적/유사도·embedding·chunk·출처와 정답의 차이 | AX-02 검색 비교 | 차원·정규화·ranking 실패에서 행렬/확률 설명 보강 |
| 함수/도구 계약·상태·부작용·멱등성·권한 | AX-03 | 중복 실행·복구·승인·prompt injection 실패에서 강화 |
| tensor/shape·미분/chain rule·gradient·loss/likelihood·확률 기초 | RE-01 학습 전에 | gradient·학습/검증 격차·일반화 가설과 함께 정규화·최적화·추론 통계 보강 |
| token shift·softmax/CE·attention/mask·조건부확률 | RE-02 의존 구현 전에 | 수치 안정성·계산량·모델 실패를 보고 필요한 유도/계산 추가 |
| base/instruct·chat template·loss mask·SFT 목적·학습/평가 오염 | RE-03 후속학습 전에 | 데이터/최적화 가설·판정기 불일치 또는 inference 수치 허용오차에 맞춰 심화 |

수학·통계는 지우지 않는다. 사용하지 않는 긴 선행 과정을 줄이고, 실제 모델/실험이 요구하는 깊이로 늘린다. 튜터 설명이나 과정 이수는 학습자가 설명·구현·실험한 근거를 대신하지 않는다.
