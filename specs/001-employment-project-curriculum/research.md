# 설계 조사: 직무·교육과정 근거와 커리큘럼 선택

**조사일**: 2026-10-19 · **기준**: [수정 명세](spec.md), 헌법 1.0.0 · **상태**: 2026-10-19 수정 명세·계획 사용자 승인

이 문서는 자료의 관찰과 설계 결정·이유·대안을 구별한다. 학습자의 실행·숙달·취업 또는 새 운영 경로의 적용을 입증하지 않는다. 사내비 예시를 필수 과정으로 해석한 이전 설계는 폐기했다.

## R0. 조사 범위와 근거의 품질

- **결정**: [한국/미국 JD](research/jd-evidence.md), [교육과정](research/reference-curricula.md), [AX 기술 동향](research/trend-evidence.md)을 별도 검토하고 [선택 매핑](research/decision-matrix.md)으로 연결한다.
- **근거**: 상세 본문을 직접 검토한 JD는 한국 7개·미국 6개다. 한국 ATS 2개는 인덱스만 확인해 보조로 분리했다. 공식 교육과정 10개와 동향 8개를 비교했고, 동향에는 2026년 원문 6개가 포함된다. 검색 목록만 본 페이지·접근 실패·마감/불명을 현재 채용으로 세지 않았다.
- **한계**: 목적 표본은 경력직/주요 AI 기업에 치우쳤다. 전체 채용 시장·입문자 수요·이 학습자의 자격/취업 시점을 확정하지 않는다. 기업 telemetry와 제품 설명도 전체 산업 통계나 인과 효과가 아니다.
- **대안**: 사용자 예시에 최신 링크 몇 개만 붙이는 방법, 유명 과정 여러 개를 전부 수강시키는 방법, 검색 요약으로 JD를 채우는 방법을 제외했다.

## R1. 개편의 구현 기술과 범위

- **결정**: Markdown 운영 문서, 기존 Python/pytest 문서 검사, 학습 스킬의 계약을 개편한다. 앱·서버·DB·자동 다음 활동 선택기를 만들지 않는다.
- **근거**: 현재 lab은 Python 3.14와 uv 환경이고 공개 CI는 기존 pytest 경로를 사용한다. 문서 규칙의 이행에 새 패키지나 런타임은 필요하지 않다. 환경 설정과 실제 학습자 코드 실행은 다른 사실이다.
- **대안**: 새 포트폴리오 앱을 먼저 생성하면 학습자 대상 구현을 대행한다. YAML 학습 DB·시간/진도 엔진은 단순 북마크 목적과 맞지 않는다.
- **후속 처리**: 실제 프로젝트에서 사용할 API/모델·패키지·장치 호환성과 자료/비용은 그 활동 전에 확인한다. 이번에는 pyproject·lock·커널·명령 설정을 바꾸지 않는다.

## R2. AX 기본 프로젝트와 순서

- **결정**: 업무 문의 처리 보조 서비스 하나를 AX-01 작은 AI 기능→AX-02 데이터/검색→AX-03 도구/workflow→AX-04 서비스 품질로 발전시킨다. 사내비 Q&A는 대체 후보다.
- **이유**: JD의 업무/데이터/API 연결·평가·운영 요구와 HF Agents·FSDL의 선택 주제를 같은 산출물에서 확인할 수 있다. 정상/불완전/범위 밖 입력부터 결과를 보고, 실제 부족한 지식·행동·운영 책임을 추가한다.
- **선택 경계**: TF-IDF는 sparse baseline의 후보, 분류/분류 파인튜닝·MCP는 task-specific 선택, framework는 상태/도구를 설명할 한 개(기본 LangGraph)다. multi-agent·A2A와 여러 framework 전체 학습은 보류한다. 상세 이유와 복귀 조건은 선택 매핑에 있다.
- **대안**: 고정 TF-IDF→분류→LangChain은 사용자가 정한 요구가 아니다. 처음부터 만능 agent나 대규모 모델을 만들면 첫 유용한 결과까지 장애가 겹친다. 이 순서를 공식 기관의 필수 순서나 검증된 최적 일정으로 부르지 않는다.
- **최소 산출물**: AX-01의 작은 기능+여섯 설명 근거는 조기 공고 비교의 시작이다. 주 포트폴리오 목표는 AX-01~04 한 서비스이며 RE 전 과정·선택 파인튜닝·외부 배포는 선행 조건이 아니다.

## R3. 선수와 첫 평가

- **결정**: Python/요청 계약·LLM 비결정성·평가 사례의 역할을 첫 기능 전에, 벡터/근거를 검색 전에, 도구 상태/부작용을 workflow 전에 설명한다. 모델 작업에는 tensor/loss·gradient·학습/검증을 먼저 다룬다.
- **이유**: 기초를 삭제하지 않으면서 쓰임 없는 장기 선행 수강을 줄인다. 실제 사용처와 오류에서 필요한 깊이를 늘린다. 자세한 시점은 선택 매핑 5절에 있다.
- **평가 설계**: 독립 사례·중복/그룹·개발과 최종 평가·지표·오류·소표본 한계를 첫 비교부터 둔다. 고정 검색 corpus의 색인과 질의/qrels의 모델 선택 사용은 다르다. 분류를 선택하면 split 뒤 전처리/모델 fit·선택을 train/dev로 제한한다. 실제 outcome과 agent가 보고한 성공도 구분한다.
- **기술 참고**: [scikit-learn 누수/전처리 원리](https://scikit-learn.org/stable/common_pitfalls.html), [그룹/모델 선택과 CV](https://scikit-learn.org/stable/modules/cross_validation.html), [Microsoft RAG 설계/평가](https://learn.microsoft.com/en-us/azure/architecture/ai-ml/guide/rag/rag-solution-design-and-evaluation-guide), [Anthropic evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents). API 호환 실행을 검증한 것은 아니며 활동 시 사용하는 판본을 확인한다.
- **대안**: 평가를 마지막 포트폴리오 단위로 미루거나, 검색 corpus를 분류 train/test처럼 무조건 나누거나, 반복 생성 횟수를 독립 질의 수로 부풀리지 않는다. 마지막 자료를 보고 바꿨다면 미사용 test라고 하지 않는다.

## R4. 구체적인 LLM Research Engineer 후속 경로

- **결정**: RE-01 학습/검증 실험→RE-02 작은 LM 하나→RE-03 전문화 한 비교→RE-04 독립 질문 cycle을 설계한다. 각 범위에 목적·직접 산출물·선수·자료·진입 근거가 있다.
- **이유**: 모델/연구/시스템 JD는 단순 앱 연결과 다른 학습·실험·성능 근거를 요구한다. MIT 6.S191 2026의 기반 설명, HF의 모델/데이터·SFT/평가, CS336 2026의 LM/data/eval 범위를 선택적으로 쓸 수 있다. 수학·최적화·통계는 모델·실험 의존 시점에 실제 깊이를 유지한다.
- **전문화 선택**: 기본안 post-training/evaluation은 AX에서 생긴 행동/평가 문제를 학습 신호로 연결한다. 실제 목표가 inference/systems에 더 맞으면 한 갈래를 대체한다. DPO/RLVR·kernel/분산을 모두 의무화하지 않는다.
- **LM 중복 방지**: 기본은 독립 자체 LM 하나다. 공식 CS336 A1을 선택하면 같은 구현을 대체하며 기존 private clone·A1 pin·별도 환경·AI/명령 제한을 보존한다. 작은 로컬 모델 실행을 공식 과제 전체 완료로 부르지 않는다. 정책이 더 엄격하면 그 정책을 따른다.
- **대안**: ‘취업 후 연구 복귀’ 한 문장만 남기기, 전체 CS229/CS231n/CS224N/CS336을 다시 선행 의무로 쌓기, 같은 LM 두 개 전체 구현, 학원 수료나 작은 프로젝트로 학위/대규모 연구 요건을 대신한다고 하기 모두 제외했다.

- **근거**: 기존 `.gitignore`는 `/practice/private/`를 제외한다. 두 경로와 `practice/reviews/curriculum-transition.md`는 2026-10-19 존재하지 않았다. 실제 준비 직전에 충돌과 공개 권리를 다시 확인한다.
- **과거 근거**: STATE에는 Part 4 미작성 기울기·도움·독립 회상 미확인 등 유일한 근거가 있다. 실제 적용 직전 원문 전체를 새 transition 문서에 한 번 인용하고 상대 링크 목적지·미완료/도움 의미를 검증한 뒤 현재 북마크를 이행한다. 기존 회고는 재작성하지 않는다.
- **첫 행동**: 튜터가 문제/출력/흐름과 최소 선수를 설명하고 환경·문의 원자료·빈 공간을 준비한다. 학습자는 식별자·본문을 읽어 입력 계약을 확인하는 처리 코드를 먼저 작성/실행하고 AX-01의 구조화 초안 흐름으로 이어간다. 별도 긴 기획 답안·전체 수학 진단을 시작 gate로 두지 않는다. 준비·실행은 아직 수행하지 않았다.
- **대안**: 사내비 수정, 기존 노트북 초기화·코드 통째 복사, 과거 북마크 삭제로 해결하지 않는다. 현재 재개는 STATE만 정하고 transition 인용을 두 번째 STATE로 쓰지 않는다.

## R7. 지침 길이와 기준 문서 분리

- **결정**: 루트 AGENTS는 핵심·권한·문서 역할·필독을 앞에 두고 내부 예산 12 KiB 이내로 정리한다. 상세 정책은 새 `.agents/references/learning-policies.md` 한 파일로 분리하고 명시적으로 읽도록 한다. `CLAUDE.md -> AGENTS.md` 연결을 유지한다.
- **근거**: 현재 루트 AGENTS는 571줄·37,338 bytes이고 선행 실행에서 지침 잘림 경고를 실제 관찰했다. 12 KiB는 자체 기준이며 모든 도구의 적재 한도를 보장하는 사양이 아니다.
- **대안**: 링크만 두고 자동 발견을 가정하거나 전역 도구 설정을 늘리지 않는다. 이동한 절 링크도 함께 고친다.
- **검증**: 정적 크기/링크·symlink 검사와 실제 현재 도구의 필독 확인은 별개다. 한 도구에서 본 결과를 다른 도구의 로딩 성공으로 확대하지 않는다.

## R8. 검증과 남은 사실의 경계

- **결정**: 기존 순서/시간/전체 과제 의무 검사를 새 AX/RE 계약으로 대체하되 소유권·준비·기록/공개·단일 STATE·공식 과제/CS336·종료 권한과 과거 감사/registry 보존을 계속 검사한다.
- **근거**: 현재 검사에는 바뀌어야 할 고정 경로와 유지할 보존/권한 규칙이 함께 있다. 문자열 검사나 합성 튜터 응답 검토는 실제 학습 효과와 다르다.
- **대안**: 검사 전체 삭제, 문구만 맞춰 교육 효과 주장, 계획에서 실제 학습 코드·유료 평가를 실행하는 방식은 제외한다.
- **남은 확인**: 실제 데이터/모델 권리·환경/자원·패키지/API·비용, 새 컨텍스트 필독, 학습자 직접 수행·지연 회상·취업은 해당 시점의 사실이다. 이 계획에 숨은 필수 주제나 미정 순서를 남긴 것이 아니며 지금 수행 완료라고 하지 않는다.
