# 학습 인터페이스 계약

**상태: 2026-10-19 수정 명세·계획 사용자 승인.** 현재 학습 위치는 STATE만 정하며 구현에서 원문 보존 후 이행한다. 이 문서는 승인 후 ROADMAP·CURRICULUM·AGENTS·study-session에 반영할 계약이며 학습자 코드·답안·진도표가 아니다. 단위별 근거/자료는 [선택 매핑](../research/decision-matrix.md), 자료 접근/판본은 [교육과정 비교](../research/reference-curricula.md)에 둔다.

## C1. 시작·재개와 단위 진행

- `오늘 학습 시작`과 전체 흐름 시작은 STATE의 현재 승인 단위에서 출발한다. `계속`은 다음 독립 행동 하나를 재개한다. 전 과정 재진단·긴 기획 답안·옛 과목 재시작을 첫 행동으로 요구하지 않는다.
- 튜터는 현재 단위의 문제·필요성·앞뒤 흐름·입출력·자료 구간과 최소 선수를 설명하고 허용된 환경/자료/빈 공간을 준비한다. 학습자는 다음 작은 구현·실행·첫 해석을 맡는다.
- 실제 시도·해석을 검토한 뒤 승인 범위의 다음 활동으로 연결한다. 매 단계 계속할지 재승인을 요구하지 않으며 학습자의 답이나 실행이 필요한 곳에서 기다린다. 신규 과정·범위 변경이나 별도 비용/게시 권한은 기존 경계를 따른다.
- API 문서를 참고한 실무 구현과 자료를 닫은 대표/지연 회상은 구별한다. 모든 호출의 문법 암기를 시작 관문으로 만들지 않는다.
- pause·변경 검토 요청은 수업 중지이며 자동 종료/커밋이 아니다. 명시적 학습 종료·실제 챕터 전환·기록 요청의 권한은 각각 유지한다. AX/RE 단위 완료만으로 finish-chapter·TIL/knowledge 작성·노트북 초기화·Git 권한이 생기지 않는다.

| 최소 선수 | base/instruct·chat template·SFT 목적·loss mask·PEFT의 역할, 독립 분리·오염·통제 비교·자원 권한 |
| 작업 중 보강 개념 | 데이터/optimization·판정기 불일치·reward 문제가 실제 드러날 때 심화. DPO/RLVR은 별도 필요/선수 확인 |

**추론/시스템 대안**은 같은 열 개 요소를 사용하되 한 모델/요청 workload→prefill/decode·cache/batching 한 변수→수치·품질·지연/처리량·메모리/병목으로 바꾼다. 고정 길이와 EOS 요청, cache 수치 허용오차와 양자화 품질 허용오차를 구별한다. 단일 장치 결과를 B200·다중 GPU 완료로 기록하지 않는다. SFT와 이 대안을 모두 요구하지 않는다.

## C3. 준비·도움·실제 근거의 경계

| 상황 | 튜터의 허용 행동 | 학습자 직접 작업·근거 경계 |
| --- | --- | --- |
| 현재 승인 활동 시작 | 정확한 자료/목적 확인, 환경/커널·권리 확인 원자료·허용 starter 또는 빈 공간 준비 | 대상 구현·실행·첫 해석. 비어 있지 않은 코드 덮어쓰기 금지 |
| 실무 API 사용법 | 사용하는 판본의 공식 API와 관련 없는 작은 예제 설명 | 문서 참고로 대상 코드를 작성. 해당 target의 정확한 답안 호출/인자·골격을 대신 주지 않음 |
| 선수 공백 | 의존 작업 전에 필요한 개념을 목적/사용처와 함께 설명 | 해당 구현/해석에서 사용. 전체 과목 재시작이나 모든 API 암기 gate 없음 |
| 실제 오류 | 현재 코드·저장 출력 확인, 변경 전 원인 가설/확인 방법을 듣고 한 장애씩 검토 | 직접 가설·수정·실행/해석. 오류가 없으면 가설 의무 없음 |
| 대표/지연 회상 | 환경과 빈 공간·완전한 givens 제공, 단서는 주지 않음 | 코드/수식/shape 등 해당 목표를 직접 재구성. import·signature·답안 skeleton도 없음 |
| 노트북 | `scripts/nbpeek.py`로 관련 셀/출력만 확인 | 실행/저장 없으면 미확인. 별도 권한 없이 학습자 셀 실행·코드 수리·출력 생성 금지 |
| 성능 미개선 | 비교 조건·누수·실패/불확실성과 해석 검토 | 실제 실패는 실패로 남김. 실행 불가와 부정적 실험 결과도 구별 |
| 권리/비용/배포 제한 | 사실 확인·허용된 준비와 가능한 범위 진행 | 유료/외부 게시·배포는 기존 권한 확인; 미수행 결과를 만들지 않음 |
| 공식 과제 선택 | 정확한 판본·AI/비공개/환경 정책 확인 | 공식 답안/원문은 private. CS336은 학습자가 모든 명령 실행; AI의 과제 repo bash·새 명령 시퀀스·코드/의사코드/답안 금지 |

기존 코드 복사·튜터 복구·API 참고·개념 도움·무보조 시도·새 커널 재현·지연 회상을 혼합해 독립 성공으로 쓰지 않는다. 기존 팀/사내비 결과는 새 직접 구현과 별개다.

## C4. 평가와 포트폴리오

첫 기능부터 과업·독립 사례·중복/그룹·개발/최종 평가·지표·모델 선택 범위·오류를 설명한다. 검색 corpus 색인과 질의/정답 사용, 분류/학습의 train-only fit, 최종 평가를 본 뒤 수정한 사실을 구별한다. 에이전트는 실제 상태/권한/실패로 평가하며 trace만 보고 성공을 단정하지 않는다. LLM judge를 쓰면 사람 기준과 불일치를 확인하고 자동 점수를 정답으로 취급하지 않는다.

지원용 최소 설명 항목은 **사용자 문제·직접 작동 기능·평가/실패·재현 조건·기여/도움·주장 한계**의 여섯 가지다. AX-01부터 조기 비교가 가능하지만 주 포트폴리오는 AX-01~04를 잇는 서비스다. 단위 수·인증·프레임워크 수가 자격이 되지 않는다. 실제 공고의 필수/우대·연차/학위와 자기 근거를 다시 읽고 대조하며, 취업 날짜·회사별 적합성을 보장하지 않는다.

## C5. 승인·기록·공개

수정 명세/계획 검토 중 운영 문서·STATE·학습 산출물은 바꾸지 않는다. 승인 후에도 TIL/knowledge·과거 회고·공개 과제 답안·유료 실행·외부 게시·Git 권한을 프로젝트 진행과 섞지 않는다. 코스 실습을 선택적으로 참고한 활동을 공식 수료/대학 채점으로 부르지 않는다. finish-chapter는 실제 챕터 전환의 근거와 별도 정책을 따른다.
