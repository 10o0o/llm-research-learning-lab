### 사용자 시나리오 1 — 첫 작동 단위부터 취업용 근거를 쌓는다 (우선순위: P1)

학습자는 조사 근거로 선택된 작은 업무 문제를 이해하고, 입력부터 유용한 결과까지 이어지는 기능을 직접 구현한다. 처음부터 대형 앱이나 긴 기초 과정을 완성해야 하는 부담 없이, 다음 개선이 왜 필요한지 관찰할 수 있다.

**우선순위 이유**: 코드를 쓰지 못하거나 목적을 모른 채 공부했던 문제를 가장 먼저 해결한다.

**독립 검증**: 첫 구현 단위의 안내만으로 문제·직접 할 일·입출력·평가·완료 경계를 식별할 수 있는지 검토한다. 이후 모든 기술을 완성하지 않아도 이 단위 자체의 실행과 해석을 확인할 수 있어야 한다. 개편 문서 검토가 실제 학습자의 구현 성공을 입증하지는 않는다.

**인수 시나리오**:

1. **조건** 학습자가 새 경로를 시작하고 관련 과목을 완강하지 않은 상태에서, **행동** 첫 단위의 안내를 확인하면, **결과** 필요한 최소 선수 설명 뒤 권리 확인된 작은 입력으로 유용한 출력과 실패 사례를 직접 확인할 일을 알 수 있다.
2. **조건** 첫 baseline만 실행·해석한 상태에서, **행동** 그 단위의 완료 여부를 검토하면, **결과** 후속 모델 학습·복잡한 에이전트·전체 앱·장기 연구 과제의 완료 없이 해당 단위만의 기준으로 판단한다.
3. **조건** baseline의 한계를 관찰한 상태에서, **행동** 다음 개선 단위를 선택된 경로에서 확인하면, **결과** 외부 지식·도구·모델·운영 개선 등 이어지는 작업의 이유와 입력·출력 관계를 조사 근거 및 현재 문제에 연결해 설명한다. 사용자 예시가 모든 프로젝트의 고정 순서로 복원되지 않는다.

### 사용자 시나리오 2 — 목적을 이해하고 직접 구현하며 공백을 메운다 (우선순위: P1)

학습자는 구현 전에 코드가 해결할 문제와 앞뒤 흐름을 배우고, 직접 작성·실행·해석한다. 문법이나 사용법은 공식 문서를 참고하고, 현재 결과를 이해하는 데 필요한 개념 공백을 작업 안에서 보강한다.

**우선순위 이유**: 프로젝트가 단순한 따라 치기나 기술 목록 소진으로 바뀌는 것을 막는다.

**독립 검증**: 구현 전 안내, API 사용법 질문, 선수 공백, 실제 오류에 대한 튜터 응답을 각각 검토한다. 학습자에게 필요한 맥락과 다음 행동이 제공되고 대상 답안은 제공되지 않아야 한다.

**인수 시나리오**:

1. **조건** 새 구현 단위를 안내하는 상황에서, **행동** 학습자가 작업을 시작하면, **결과** 사용자 문제, 구현 목적, 이전·다음 연결, 입출력, 전체 흐름, 직접 할 일, 관찰 결과, 완료 기준, 최소 선수, 작업 중 보강 개념의 10개 요소를 확인할 수 있다.
2. **조건** 실무 구현 중 API 사용법이 막힌 상황에서, **행동** 학습자가 도움을 요청하면, **결과** 튜터는 확인한 공식 문서와 관련 없는 작은 예제로 동작을 설명하고 학습자에게 대상 구현을 맡긴다. 모든 호출을 백지 암기 시험으로 바꾸지 않는다.
3. **조건** 데이터 누수 또는 텐서·손실 계약을 이해하지 못한 상태에서, **행동** 그 개념에 의존하는 작업을 안내하면, **결과** 필요한 개념을 먼저 설명하고 현재 기능에 연결한다. 전체 수학·과목 재시작을 요구하지 않는다.
4. **조건** 학습자가 오류와 실제 출력을 제시한 상태에서, **행동** 튜터가 피드백하면, **결과** 현재 파일과 출력, 변경 전 원인 가설과 확인 방법을 바탕으로 한 번에 한 장애를 다룬다. 오류가 없었던 경우에는 오류 가설을 요구하지 않는다.

### 사용자 시나리오 3 — 최소 포트폴리오를 설명하고 지원 판단에 사용한다 (우선순위: P1)

학습자는 첫 baseline 이후 지원용 최소 산출물의 경계를 확인한다. 자신이 구현한 기능, 선택 이유, 평가, 실패 사례, 재현 방법과 한계를 설명하고 실제 채용 요건과 비교할 수 있다.

**우선순위 이유**: 취업이 단기 최우선인 만큼 모든 후속 학습이 끝나기 전에 지원 판단에 쓸 근거가 필요하다.

**독립 검증**: 최소 산출물의 정의를 읽고 후속 심화 없이도 검토할 자료와 미검증 범위를 식별할 수 있는지 확인한다. 특정 공고가 제시되면 원문 요건과 실제 기여를 비교하는 절차를 검토하며 채용 결과는 개편의 합격 기준으로 삼지 않는다.

**인수 시나리오**:

1. **조건** 작은 기능의 직접 구현과 실행 근거가 있는 상태에서, **행동** 최소 산출물 충족 여부를 검토하면, **결과** 사용자 문제·작동 기능·평가와 실패 사례·재현 조건·기여와 도움·주장 한계의 6개 항목을 확인하며 거대 앱 완성이나 전 기술 이수를 추가 조건으로 붙이지 않는다.
2. **조건** 파인튜닝이나 생성 연결 후 성능이 개선되지 않은 상황에서, **행동** 결과를 검토하면, **결과** 비교 조건·오류·한계를 해석한 결과로 남기고 없는 개선 수치를 만들거나 성공으로 승격하지 않는다.
3. **조건** 실제 지원 대상을 검토하는 상황에서, **행동** 공고와 산출물을 대조하면, **결과** 확인한 원문 요건과 자기 기여를 비교한다. 특정 주수의 취업, 직무 적합성 또는 기존 다른 언어 경력의 자동 환산을 보장하지 않는다.

### 사용자 시나리오 4 — 새 경로로 재개하면서 과거 기록을 보존한다 (우선순위: P1)

학습자는 승인된 개편이 적용된 뒤 다른 AI 도구나 새 대화에서도 하나의 북마크로 다음 직접 작업을 이어간다. 예전 과정의 미완료·도움·실행 근거는 보존하며 새 프로젝트를 시작하는 장애로 되살리지 않는다.

**우선순위 이유**: 기존 기록을 손상시키거나 옛 필수 규칙이 다시 작동하면 개편 후에도 같은 학습 문제가 반복된다.

**독립 검증**: 적용 전후의 보존 대상과 현재 북마크를 비교하고, 새 대화의 시작·재개 사례를 검토한다. 다음 행동은 하나여야 하며 기존 미완료 근거의 보존 위치를 찾을 수 있어야 한다.

**인수 시나리오**:

1. **조건** 승인 전 명세·계획 검토 단계에서, **행동** 이 단계를 완료하면, **결과** 기존 STATE와 운영 문서는 그대로 남고 새 경로는 명세로만 존재한다.
2. **조건** 명세와 계획의 사용자 승인 후 개편을 적용하는 상황에서, **행동** STATE를 이행하면, **결과** 새 경로의 확인된 현재 범위와 다음 독립 행동 하나를 남긴다. 기존 makemore Part 4 수동 역전파 등 미완료·도움 근거의 보존 방법도 함께 확인하며 완료로 처리하지 않는다.
3. **조건** 새 경로가 적용된 뒤 다른 도구에서 `계속`을 요청하면, **행동** 튜터가 현재 위치를 확인할 때, **결과** STATE를 기준으로 같은 작업을 재개한다. 옛 과목 순서·임시 파일·대화 기억·노트북 메타데이터로 다른 현재 위치를 선택하지 않는다.

### 사용자 시나리오 5 — 장기 연구 목표에 필요한 깊이로 돌아간다 (우선순위: P2)

학습자는 취업용 직접 구현을 우선하면서도 장기 LLM Research Engineer 목표에 필요한 모델·수학·실험·시스템·연구 경로를 확인한다. 이 경로도 검증된 레퍼런스에서 선택하며 단계별 직접 산출물·선수·진입 조건을 갖춘다. 현재 문제나 실제 요구에 필요한 범위부터 깊이를 늘린다.

**우선순위 이유**: 단기 우선순위 변경이 장기 목표 삭제나 기초 개념의 무조건 생략이 되어서는 안 된다.

**독립 검증**: 기존 필수 항목의 새 역할과 제외 이유·복귀 조건을 대조하고, 실제 개념 공백이 생기는 사례에서 필요한 범위만 제안하는지 확인한다.

**인수 시나리오**:

1. **조건** 기존 과목·문제세트·재구현 요구를 재검토하는 상황에서, **행동** 새 경로와 보류 자료를 읽으면, **결과** 필수·선택·보류의 역할이 구분되고 제외 항목마다 이유와 관찰 가능한 복귀 조건이 있다. 선택 해제는 완료가 아니다.
2. **조건** 현재 작업 또는 확인한 직무·연구 요구에 개념 공백이 드러난 상황에서, **행동** 후속 학습을 검토하면, **결과** 모델 학습 기반·언어모델 내부·하나의 전문화·독립 실험을 포함한 구체 경로에서 필요한 보강과 다음 산출물을 찾을 수 있다. 전체 연구 경로를 첫 프로젝트나 지원의 선행 관문으로 만들지 않는다.
3. **조건** 공식 과제를 다시 선택한 상황에서, **행동** 준비와 도움 범위를 정하면, **결과** 확인한 판본·AI 정책·비공개 공간·별도 환경·명령 제한을 따른다. 프로젝트 구현을 공식 과제 전체 완료로 대신하지 않는다.

4. **조건** 연구와 취업 경로를 재설계하는 상황에서, **행동** 조사 자료와 선택 근거를 검토하면, **결과** 한국·미국 JD와 대학·기업 교육과정의 실제 요건, 선택한 역량·프로젝트·자료 구간, 제외 이유를 추적할 수 있다. 시니어·학위 요구나 특정 기업의 제품 홍보를 보편적 입문 조건으로 바꾸지 않는다.

### 경계 사례

- **기존 사내비 코드나 팀 산출물을 통째로 복사한 경우**: 참고·복구·도움의 출처를 구분하며 새 독립 구현으로 세지 않는다. 원래 저장소나 배포는 변경하지 않는다.
- **새 작업 공간에 기존 학습자 코드가 있는 경우**: 덮어쓰지 않고 충돌을 알린다. 공간의 위치·분리 방법은 계획에서 정하며 기존 노트북을 초기화하는 것으로 해결하지 않는다.
- **시작에 필요한 환경·커널이 준비되지 않은 경우**: 튜터가 허용된 준비를 해결하거나 실제로 필요한 정보만 확인한다. 설치나 커널 수리를 학습자 구현 과제로 넘기지 않는다.
- **공식 자료의 정확한 구간에 접근할 수 없는 경우**: 해당 자료 의존 설명만 멈추고 한계를 밝힌다. 제목이나 기억으로 원문을 지어내지 않는다.
- **자료가 작거나 중복·그룹 의존성이 있는 경우**: 표본 단위와 분리의 한계를 밝힌다. 반복 실행 수를 독립 평가 사례 수로 부풀리지 않는다.
- **검색과 분류의 평가 구조가 다른 경우**: 검색 대상 문서의 색인과 평가 질의·정답을 모델 선택에 사용하는 행위를 구분한다. 분류용 분리 규칙을 검색에 무조건 복사하지 않는다.
- **소규모 비교에서 새 모델이 baseline보다 나쁜 경우**: 실패와 원인 분석을 유효한 결과로 다루며 반드시 향상해야 다음 단위로 갈 수 있는 조건을 만들지 않는다.
- **공개 권한·개인정보·라이선스·유료 자원 문제가 있는 경우**: 해당 데이터나 실행은 보류한다. 권리가 확인된 자료로 수행 가능한 범위와 미수행 범위를 구분하고 비용 승인 전 유료 실행을 하지 않는다.
- **로컬 실행만 확인된 경우**: 운영 가능한 전체 서비스, 실제 배포, 장기 기억 또는 채용 적합성의 증거로 확대하지 않는다.
- **운영 문서와 검사가 새 경로에 모순되는 경우**: 의도적으로 바꿀 경로 규칙과 유지할 보존·소유권 규칙을 구별해 수정한다. 검사 전체 삭제로 모순을 숨기지 않는다.
- **공통 지침이 실행 도구의 읽기 한도를 넘는 경우**: 핵심 규칙과 필수 참조가 잘려 누락되지 않도록 지침의 책임과 배치를 정리한다. 다른 문서로 옮겼다는 사실만으로 실제로 읽히는 것이 확인되었다고 보지 않는다.
- **공고가 마감됐거나 동적 페이지를 읽지 못한 경우**: 조회일·게시/마감일·본문 접근 방법·불명 상태를 구별한다. 검색 요약만 본 공고는 원문 직접 검토 표본에 넣지 않는다. 과거 JD는 요구 역량의 과거 사례이며 현재 채용의 증거가 아니다.
- **레퍼런스가 오래됐거나 기업 제품에 치우친 경우**: 판본과 한계를 표시하고 다른 원문과 대조한다. 설계 원리와 현재 API·제품명을 분리하며 수강 등록·유료 실행·전 과목 이수를 자동 요구하지 않는다.

### 기능 요구사항

- **FR-001**: 새 경로는 AX/AI 애플리케이션 지원용 직접 구현과 설명 가능한 포트폴리오를 단기 최우선으로 명시하고 LLM Research Engineer를 장기 목표로 보존해야 한다. 취업·완료 시점이나 고용 가능성을 보장하는 표현을 두지 않아야 한다.
- **FR-002**: 첫 작동 baseline은 조사 근거로 선택한 작은 업무 문제의 입력부터 유용한 출력·사전 정한 평가·실패 사례 해석까지 이어지는 독립 완료 단위여야 한다. 광범위한 수학, 과목 완강, 공식 문제세트 전체, 후속 심화를 그 시작이나 완료의 선행 조건으로 두지 않아야 한다. 튜터의 맥락 설명과 허용된 준비 후 의미 있는 첫 코딩으로 이어져야 한다.
- **FR-003**: 취업 경로의 모든 구현 단위는 사용자 문제, 구현 목적, 이전·다음 연결, 입력·출력, 전체 데이터 흐름, 학습자 직접 작업, 관찰 결과, 완료 기준, 최소 선수, 작업 중 보강 개념의 10개 요소를 제공해야 한다. 필수 선수는 사용처를 명시하고 작업 중 보강 개념은 관찰할 공백 또는 오류와 연결해야 한다.
- **FR-004**: 취업 경로의 주제·순서는 최근 동향, 실제 직무의 업무·요건, 레퍼런스 교육과정의 선수·실습과 학습자의 기존 근거를 대조해 구성해야 한다. 사내비·TF-IDF·분류기·파인튜닝·LangChain을 사용자 지정 필수 주제나 고정 순서로 간주하지 않아야 한다. 이들의 채택·선택·보류에는 해결할 문제와 이유가 있어야 한다.
- **FR-005**: 각 후속 단위는 이전 결과의 어떤 한계를 확인하거나 개선하려는지와 결과를 판단할 비교 기준을 명시해야 한다. 라이브러리·프레임워크·프로토콜은 연결 전후의 데이터 흐름과 해결하는 작업으로 설명하고, 도구 사용 자체를 이해나 품질 개선의 근거로 삼지 않아야 한다. 유행이라는 이유만으로 복잡한 에이전트나 다중 프레임워크를 병렬 필수화하지 않아야 한다.
- **FR-006**: 첫 baseline과 지원용 최소 산출물의 경계를 각각 명시해야 한다. 최소 산출물은 사용자 문제, 직접 만든 작동 기능, 평가·실패 사례, 재현 조건, 자기 기여·도움, 주장 한계의 6개 항목을 포함해야 하며 이후 심화 전체를 요구하지 않아야 한다. 최소 산출물 충족을 모든 직무의 지원 자격 충족으로 해석하지 않아야 한다.
- **FR-007**: 필수 선수는 의존 작업 전에 필요한 범위로 가르쳐야 한다. 입력·라벨·텐서·손실의 기본 계약은 관련 모델 작업 전에, 분리·누수 방지·지표·baseline의 의미는 첫 평가와 비교 전에 제공하고 다른 공백은 현재 구현·오류·실험 안에서 보강해야 한다.
- **FR-008**: 기존 P0~P5 고정 순서, MML·MIT 기초 범위, makemore 후속 실습, CS229 PS1~PS3·ISLP, CS231n·CS224N 선택 과제, CS336 A1·A2, 대회·대표 재구현·기존 시간 배분의 의무 여부를 모두 재검토해야 한다. 새 역할과 이유를 정하고 선택 해제 항목이 다른 지침·검사의 숨은 선행 관문으로 남지 않게 해야 한다.
- **FR-009**: 제외·보류 항목마다 제외 이유와 현재 작업·실제 직무·연구 요구에서 관찰할 수 있는 복귀 조건을 기록해야 한다. 조건 관찰만으로 새로운 과목·트랙을 자동 시작하거나 과거 미완료를 완료로 바꾸지 않아야 한다. 이미 승인된 범위의 통상 진행에는 반복 승인을 요구하지 않아야 한다.
- **FR-010**: 평가는 첫 baseline부터 포함해야 한다. 과제별 평가 대상·독립 표본 단위·중복과 분리 규칙·지표 선택 이유·모델 선택 범위·최종 평가의 사용 경계·오류 사례를 명시해야 한다. 검색 대상 문서의 색인과 평가 질의·정답의 학습 사용은 구분해야 한다.
- **FR-011**: 비교와 파인튜닝 단위는 baseline, 변경 요인, 비교 조건, 실제 실행 결과, 오류분석과 주장 한계를 요구해야 한다. 전처리·모델 선택의 누수, 중복 자료, 반복 실행과 독립 표본의 차이, 작은 표본의 불확실성을 관련 시점에 다루고 손실 감소만으로 품질 개선을 인정하지 않아야 한다.
- **FR-012**: 실행·운영 단위는 입력·출력 계약, 재현에 필요한 환경·실행 조건, 대표 실패·오류 대응, 비용·응답시간·품질 중 해당 기능에 필요한 관찰과 한계를 포함해야 한다. 로컬 실행·테스트·실제 배포·운영 검증을 구별하고 외부 배포를 최소 산출물의 자동 의무로 두지 않아야 한다.
- **FR-013**: 공식 문서를 참고하는 실무 구현과 자료 없이 하는 대표 회상·재구현을 구별해야 한다. 모든 API를 매번 백지 암기 대상으로 만들지 않으며 대표 확인과 지연 회상은 실제 학습 근거와 관찰된 공백에 연결해야 한다. 도움 뒤 성공이나 같은 날 실행을 무보조·장기 숙달로 기록하지 않아야 한다.
- **FR-014**: 학습자는 대상 코드를 직접 작성·실행·해석해야 한다. 튜터는 목적·개념·공식 API와 관련 없는 작은 예제를 설명하고 실제 시도를 검토하되, 학습자가 직접 만들어야 할 앱·모델·학습 데이터·답안 코드·답을 담은 골격을 대신 완성하지 않아야 한다. 허용된 원자료·제공 스타터의 준비는 FR-015에 따르며, 문서 개편 작업이 학습자 구현의 대행 권한이 되지 않아야 한다.
- **FR-015**: 현재 승인된 활동의 허용된 환경·커널·시작 자료 준비는 튜터 책임으로 유지해야 한다. 제공 스타터, 기존 코드 재현, 무보조 구현을 구분하고 기존 학습자 코드를 덮어쓰거나 고치지 않아야 한다. 준비 실패 시 필요한 사실을 확인하며 준비 책임을 학습자 다음 구현 과제로 넘기지 않아야 한다.
- **FR-016**: 수업은 검증한 정확한 공식 자료·판본·구간과 필요한 조건을 바탕으로 설명해야 한다. 원문 접근이 불가능하면 그 자료에 의존하는 설명의 한계를 밝히고 필요한 구간을 확인해야 한다. 수강·독서·실행·이해를 지어내지 않아야 한다.
- **FR-017**: 피드백은 실제 학습자 코드·저장 출력·해석을 기준으로 해야 한다. 노트북은 필요한 셀과 출력을 `scripts/nbpeek.py`로 확인하고, 학습자 실행 없이 재실행하거나 출력 이력을 고쳐 완료 근거를 만들지 않아야 한다. 오류 가설은 실제 오류가 발생했을 때만 확인해야 한다.
- **FR-018**: 기존 knowledge, TIL, 실습 코드, 노트북·저장 출력, 회고, archive, 원자료·비공개 공간을 보존해야 한다. 과거 수행·도움·미완료를 새 경로에 맞게 재작성하거나 완료·독립 구현·새 환경 재현으로 승격하지 않아야 한다. 과거 자료 감사 기록을 새 자료의 검증 결과로 바꾸지 않아야 한다.
- **FR-019**: 기존 사내비는 여러 프로젝트 후보 중 하나인 참고 예시로만 사용하고 원래 저장소·배포를 수정하거나 실행하지 않아야 한다. 기존 코드·팀 결과를 가져온 경우 출처와 도움을 구분하고 새 학습자 독립 구현으로 기록하지 않아야 한다. 문제·자료 권리·평가 가능성·직무 연결을 기준으로 후보를 비교해 계획에서 기본 프로젝트를 제안해야 한다.
- **FR-020**: 새 프로젝트 학습 공간은 기존 실습·비공개 원본과 충돌하지 않아야 한다. 위치·분리·공개 범위·기존 코드 참고 방식은 계획에서 결정하되, 비어 있지 않은 작업 공간의 무단 덮어쓰기나 기존 노트북 초기화를 개편의 기본 동작으로 삼지 않아야 한다.

### 핵심 대상

아래 대상은 문서의 의미를 정의한다. 새로운 저장 시스템이나 관리 체계를 요구하지 않는다.

- **프로젝트 맥락**: 해결할 사용자 문제, 입력 자료의 권리, 기대 출력과 사용 범위. 기존 사내비의 성과를 새 직접 구현과 구별한다.
- **조사 근거**: 확인한 JD·동향·교육과정 원문과 조회일·판본·접근 한계. 직접 관찰과 설계 해석을 분리하며 진도나 학습자 점수를 담지 않는다.
- **구현 단위**: 하나의 관찰 가능한 작동 결과를 목표로 하는 학습 범위. 10개 안내 요소와 이전·다음 단위의 연결을 가진다.
- **지원용 최소 산출물**: 지원 판단에 제출·설명할 수 있는 작은 기능과 근거 묶음. 완료 경계와 남은 심화를 구별한다.
- **학습 근거**: 기존 또는 새 학습자의 직접 작성·실행·해석, 도움, 실패·미확인 범위. 문서 계획이나 튜터 설명과 구별한다.
- **보류 항목과 복귀 조건**: 현재 경로에서 제외한 범위, 이유와 재검토를 촉발하는 구체적 필요. 과거 완료 상태를 기록하지 않는다.
- **현재 재개 북마크**: 현재 승인 범위·간결한 근거·핵심 재확인 항목·다음 독립 행동 하나. 현재 위치는 STATE에서만 관리한다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

다음 기준은 개편 문서와 튜터 운영 규칙의 인수 기준이다. 학습자의 실제 구현·지연 회상·취업 결과는 후속 실제 근거로 확인하며 이번 문서 작성만으로 달성했다고 보고하지 않는다.

- **SC-001**: 첫 작동 단위 1개 이상에 대해 입력부터 결과·평가·실패 해석까지의 완료 경계를 찾을 수 있고, 기초 완강·전체 문제세트·후속 심화가 그 시작의 선행 조건으로 붙어 있는 사례가 0개다.
- **SC-002**: 취업 경로의 구현 단위 100%에 FR-003의 안내 요소 10개가 모두 있다. 각 단위의 완료 기준을 읽으면 학습자가 직접 할 일과 확인할 결과를 추가적인 목적 질문 없이 식별할 수 있다.
- **SC-003**: 지원용 최소 산출물의 경계가 최소 1개 정의되고 6개 설명 항목을 모두 확인할 수 있다. 이후 심화의 미완료와 해당 최소 경계의 충족 여부를 별도로 판단할 수 있다.
- **SC-004**: 재검토 대상인 기존 의무 규칙 100%의 새 역할과 이유를 확인할 수 있고, 제외·보류 항목의 복귀 조건 누락 및 활성 문서·검사 사이의 필수·선택·보류 충돌이 각각 0개다.
- **SC-005**: 보존 대상으로 정한 기존 학습 산출물의 개편에 따른 수정·삭제·이동이 0건이고 과거 미완료·도움의 완료 또는 독립 근거 승격이 0건이다. 현재 북마크에서 옮겨야 하는 유일한 과거 근거는 이행 전후 모두 접근할 수 있다.
- **SC-006**: 시작, 재개, 문서 참고 도움, 선수 공백, 실제 오류, 성능 미개선, 권리·비용 제약, 공식 과제 재선택의 8개 대표 상황에서 다음 허용 행동·학습자 직접 작업·근거의 한계를 각각 식별할 수 있다. 대상 답안 대행과 미실행 결과 생성은 모두 0건이다.
- **SC-007**: 개편 적용 후 현재 재개 북마크는 1개이며 다음 독립 행동도 1개다. 새 대화 또는 다른 도구의 재개 검토에서 동일한 현재 범위를 찾고 과거 미완료를 현재 필수 작업으로 자동 복원하지 않는다.

## 가정과 의존성

- **A-001**: 주사용자는 기존 소프트웨어 개발 경험과 이 저장소의 학습 기록이 있는 학습자다. 첫 활동을 정하기 위한 전체 재진단이나 새 진도 관리 시스템은 필요하지 않다. 기존 다른 언어 경험을 특정 AI 직무의 검증된 실무 경험으로 환산하지 않는다.
- **A-002**: 첫 문제·프로젝트·순서는 조사와 후보 비교 후 계획에서 제안한다. 사용자는 설계 책임을 튜터에게 요청했으므로 새로운 긴 기획 답안이나 전체 재진단을 학습자에게 선행 과제로 넘기지 않는다. 새로운 완성 앱·학습 데이터·대상 코드를 이 단계에서 만들지 않는다.
- **A-003**: TF-IDF·분류모델 파인튜닝·LangChain은 채택 여부를 비교할 예시다. 특정 모델·라이브러리 버전·API·배포 구조·데이터셋·학습 공간의 위치를 이 명세에서 확정하지 않는다.
- **A-004**: 확인한 현행 경로는 수학·기존 모델 재현에서 전체 문제세트와 신경망 과제·작은 언어모델·전문화·연구로 이어진다. 이 순서와 필수 범위 자체가 이번 개편 대상이다. 기존 검사 통과를 위해 이를 불변 조건으로 보존하지 않는다.
- **A-005**: 개편 직전 STATE의 다음 작업은 makemore Part 4 Exercise 1의 수동 기울기 구현·비교였다. 이는 당시 북마크의 확인이며 학습자의 새 실행을 확인한 것이 아니다. 원문 근거를 먼저 보존한 뒤 북마크만 새 승인 경로로 이행하며 미완료 활동을 완료 처리하지 않는다. 적용 후 현재 위치는 STATE, 실제 이행 검증은 quickstart를 따른다.
- **A-006**: 현재 헌법 1.0.0의 취업 우선·직접 구현·맥락 선수·근거 보존·단순 운영 원칙을 적용한다. 헌법은 선행 작업의 변경으로 보존한다. 이전 명세의 “승인” 이후 사용자가 예시 해석과 조사 범위를 명확히 했으므로 수정 명세·계획은 2026-10-19 “승인할게” 응답으로 승인됐다. 실제 반영은 tasks와 구현 검증 결과로 구별한다.
- **A-007**: 실제 JD와 교육과정·동향은 계획 단계에서 조사했다. 학습에 사용할 정확한 구간·API·자료 권리·환경·비용은 필요한 활동에서 다시 확인한다. 이번 표본만으로 시장 전체 수요·지원 자격·취업 시점을 주장하지 않는다.
- **A-008**: 기존 사내비의 현재 구현·배포·품질은 이번 단계에서 재검증하지 않는다. 사용자가 제공한 프로젝트 맥락을 사용하며, 새 직접 구현으로 인정할 근거와 원래 프로젝트의 근거를 구별한다.
- **A-009**: 구현 전 검토 게이트를 거쳐야 한다. 학습 공간 방식, 기존 북마크의 유일한 근거 보존 방법, 영향받는 지침·검사의 정확한 수정 범위와 검증 방법은 계획 산출물에서 구체화한다. 이는 요구 범위의 미결정이 아니라 후속 설계 책임이다.
