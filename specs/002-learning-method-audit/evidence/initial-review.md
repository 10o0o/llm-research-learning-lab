# 학습 경로·방법·프로젝트 산출물 초기 재감사

조회 기준: 2026-10-21. 새 Spec Kit 명세 검토를 위한 초기 근거와 개선 가설이다. 아래 제안은 채택된 새 ROADMAP이나 구현 계획이 아니다. 학습 중지 요청을 유지하며 수업·모델 실행·저장소 생성·배포를 진행하지 않았다.

## 1. 검토 범위와 잠정 판단

현재 [ROADMAP](../../../ROADMAP.md)의 AX-01~04와 RE-01~04, [CURRICULUM](../../../CURRICULUM.md) 현재 구간, [DEFERRED](../../../DEFERRED.md), [운영 규칙](../../../AGENTS.md), 학습 스킬·상세 정책, 이전 001 feature의 근거, 현재 문의 보조 코드와 저장 출력을 대조했다. 역사적 보존 구간은 현재 의무로 취급하지 않는다.

잠정 판단은 다음과 같다.

- **목표의 큰 분리는 유지할 근거가 있다.** 먼저 직접 구현·평가 가능한 AI 애플리케이션 경험을 만들고, 모델 학습·작은 LM·전문화·독립 실험으로 깊이를 늘리는 구분은 실무 교육과 대학 과제의 서로 다른 목적에 맞는다. 이 순서가 개인에게 최적이거나 취업을 보장한다는 근거는 아니다.
- **현재 불편은 파일 확장자만으로 설명되지 않는다.** 실습 단위가 작은 셀·질문으로 분절되고 재사용 실행 경로와 평가 목적이 늦게 정리된 점을 우선 검토해야 한다. 노트북에서도 함수와 모듈을 재사용할 수 있다.
- **기본 서비스의 문제 적합성도 검토해야 한다.** 현재 가상 문의는 출발 자료로는 사용할 수 있지만 실제 업무 절차·담당자·평가 기준을 대신하지 않는다. 문의 보조 서비스를 유지할지, 공개 근거와 유용성을 더 분명히 검증할 수 있는 다른 문제로 바꿀지도 비교 대상이다.
- **프로젝트 본체와 실험 도구의 역할을 나누는 안이 유력하다.** 서비스 로직은 재사용 가능한 Python 코드로 관리하고, 데이터·텐서·시각화 탐색은 필요할 때 노트북에서 수행한다. 처음부터 복잡한 패키지·CI·인프라를 만드는 것은 별도의 비용이다.
- **포트폴리오용 저장소 분리는 검토할 가치가 있다.** 같은 AX 서비스는 한 저장소에서 개선 이력을 이어가고, 문제·데이터·실행 환경이 다른 연구 프로젝트는 별도 저장소로 나누는 안을 우선 비교한다. 단계별 새 저장소의 반복 생성은 기본안으로 삼을 근거가 부족하다.

## 3. 사용자가 표출한 불편과 실제 진행의 대조

선택한 발화는 현재 대화와 이전 개편의 보존 근거에서 확인한 것이다. 능력·성향을 진단하거나 전체 학습 시간을 추정하는 자료로 사용하지 않는다.

| 관찰 | 실제 진행과 대조 | 원인에 대한 판단 / 개선 가설 |
| --- | --- | --- |
| 과도한 수학 선행, 코드를 치지 않는 상황, 코드 목적·전후 사정의 불명확함 | 현재 ROADMAP에는 취업 우선·최소 선수·한 서비스 발전이 이미 명시돼 있다. 그러나 현재 보이는 활동은 입력 검사·JSON·메시지·응답 해석의 작은 단계들이다. | 큰 경로 변경만으로 실제 수업의 크기가 바뀌지는 않았다. 다음 활동을 서비스의 유용한 기능 하나와 연결하고, 그 안에서 필요한 개념을 설명하는 운영이 필요하다. |

초기화·모델 로딩 비용은 모델을 어떤 프로세스/서버에서 실행하고 무엇을 캐시하는지에 따라 달라진다. Python 파일이라는 이유만으로 매번 모델을 다시 로드한다거나, 노트북이라는 이유만으로 더 빠르다고 판단하지 않는다. 현재 로컬 모델의 새 실행·지연 측정은 이번 검토에서 수행하지 않았다.

| 단위/기능마다 새 저장소 | 문제·사용자·코드·검증·실행 환경이 실제로 독립적일 때 | 독립 사례를 보여줄 수 있지만, 같은 코드의 복제·데이터/환경 중복·이력 단절이 생긴다. 저장소 수를 늘리는 목적의 기본 방식으로 삼지 않는다. |
| 별도 LM/연구 실험 저장소 | AX와 다른 모델·데이터·환경·자원·실험 질문이 중심일 때 | 연구 질문과 실험을 집중해 설명할 수 있다. 공식 과제 답안의 비공개 제한과 자체 프로젝트의 공개 가능성을 먼저 구별한다. |

서비스를 별도 저장소로 분리할 판단 기준의 후보:

1. 해결할 사용자 문제와 범위가 한 문단으로 설명된다.
2. 실제로 실행한 최소 기능과 입력·출력 예시가 있다.
3. 코드·자료·모델의 사용/공개 권리를 구별할 수 있다.
4. 학습자 작성·튜터 도움·외부 코드의 기여가 드러난다.
5. 허용된 환경에서 다른 사람이 실행할 수 있는 의존성·설정·데이터 접근 안내가 있다.
6. baseline·실패와 알려진 한계를 설명할 수 있다.

이는 분리 검토 기준이며 취업 자격 시험이나 모든 AX 단위 완료 의무가 아니다. 초기 버전도 한계를 밝히고 발전시킬 수 있다. 새 저장소·원격 게시·배포는 검토 후 별도의 실행 범위로 다룬다.

같은 서비스의 중간 산출물은 독립 복제보다 기능 변경과 평가 결과를 버전·기록으로 남기는 안을 비교한다. 버전 이름만으로 구현·검증·배포가 완료됐다고 표시하지 않는다. 공개 README에는 문제·빠른 실행·입출력·구조·실제 평가/실패·기여·라이선스·미확인을 담는 구성이 적합하다.

## 8. 개선을 검증할 때의 기준

문서 검사를 통과하는 것과 학습 방식이 실제로 나아지는 것은 별개다. 다음은 계획 단계에서 검증 가능하게 구체화할 관찰 기준이다.

- 새 사례 실행을 위해 기존 대상 코드를 반복 복제하는지, 입력·설정 변경으로 실행할 수 있는지 확인한다.
- 학습자가 지금 해결할 문제와 본인이 바꿀 기능, 관찰할 결과가 활동 시작 전에 분명한지 확인한다.
- 의미 있는 첫 구현·실행·해석이 남는지 확인한다. 튜터가 만든 완성 코드를 실행한 사실만으로 독립 구현을 주장하지 않는다.
- 평가 기준이 모델 응답을 본 뒤 임의로 바뀌지 않는지, 불충분한 과업 정의를 학습자 오답으로 처리하지 않는지 확인한다.
- 실제 결과·모의 결과·미실행·실패·도움의 구분을 결과와 설명에서 유지한다.
- 포트폴리오 자료에 접근 가능한 실행법·실제 비교·실패·자기 기여·권리가 연결되는지 확인한다.

학습 재개 후의 실제 관찰은 아직 하지 않았다. 이번 조사만으로 학습 속도·기억·취업 확률이 개선됐다고 결론 내리지 않는다. 새 점수표·진도 DB·LMS·자동 시간표는 만들지 않는다.

## 9. 남은 확인과 다음 검토의 경계

- 현재 Python 문법의 마찰을 전체 프로그래밍 실력으로 일반화할 수 없다. 기존 실력·실제 목표 직무·독립 수행 범위는 필요한 결정 시점의 실제 근거로 확인한다.
- 현재 시간·새 연구 실험의 장치/비용 예산이 확정되지 않았으므로 고정 학습 기간이나 GPU 사용을 약속하지 않는다.
- 공식 자료의 읽기와 대학의 채점·멘토 피드백·수료는 다르다. 조사한 교육 방식을 개인 튜터 환경에 적용하는 부분은 설계 판단이다.
- 현재 자체 기능과 공식 과제의 AI/비공개 정책을 혼용하지 않는다. 새 공식 과제 선택·다운로드·clone·환경 설치는 수행하지 않았다.
- 새 명세 승인 후 조사와 설계 계획을 구체화하고, 계획 승인 후에만 운영 문서·스킬·검사의 변경을 실행한다. 현재 학습 북마크와 산출물은 보존한다.
