# AX-03 도구 선택을 위한 보충 근거

조회일: 2026-10-21. [명세](../spec.md)의 FR-004~007·012~014·022~025·034에 연결하는 공식 기술 자료다. 교육과정 표본 수를 늘리는 자료가 아니며, 아래 적용 판단은 계획 검토를 위한 제안이다.

## 1. LangGraph의 역할

출처: [LangGraph overview](https://docs.langchain.com/oss/python/langgraph/overview), Overview·Core benefits·ecosystem.

**확인한 사실**: 공식 문서는 LangGraph를 장시간 실행하고 상태를 유지하는 workflow/agent의 orchestration runtime으로 설명한다. 모델·도구 구성요소를 먼저 익힐 것을 권하며, LangChain 없이도 사용할 수 있다고 밝힌다. 결정적인 코드 단계와 모델 판단의 혼합, 중단 후 재개, 사람 개입과 상태 보존을 주요 기능으로 소개한다.

**적용 판단**: 해당 역할은 상태·재개·사람 확인을 다루는 후속 학습의 선택 근거다. 단일 구조화 응답이나 처음 만드는 도구 호출에 framework 전체를 반드시 도입해야 한다는 근거는 아니다. 현재 ROADMAP의 기본 선택을 무조건 유지하기보다 실제 필요한 책임과 연결해 검토한다.

**한계**: 제품 설명은 개인 학습 효과나 다른 구현보다 우수하다는 실험 결과가 아니다. 특정 API·버전·Python 3.14 호환·현재 앱 실행을 확인하지 않았고 설치·서비스 가입·외부 tracing도 수행하지 않았다.

## 2. 고정 흐름과 agent를 구별하는 설계 관점

출처: [Anthropic: Building effective agents](https://www.anthropic.com/research/building-effective-agents), 2024-12-19 게시, What are agents?·When (and when not) to use agents·When and how to use frameworks.

**확인한 사실**: 미리 정한 코드 경로로 연결하는 workflow와 모델이 진행·도구 사용을 동적으로 결정하는 agent를 구별한다. 단순한 해법에서 시작해 필요할 때 복잡도를 늘리고, framework를 사용해도 내부 동작을 이해할 것을 권한다. 페이지는 2024년 이후 도구 환경이 바뀌었다는 안내도 포함한다.

**적용 판단**: 먼저 고정 흐름의 입력·도구·오류·상태 결과를 이해하고, 모델 판단이 필요한 경우를 비교하는 학습 순서를 뒷받침한다. 모든 agent나 framework를 피하라는 뜻으로 사용하지 않는다. 이 자료의 과거 도구 목록을 2026년 추천 목록이나 취업 요건으로 옮기지 않는다.

**한계**: 공급자의 운영 경험과 권고이며 교육적 인과 효과·개인 적합성을 입증하지 않는다. 새 모델·SDK·managed service의 성능·비용은 이번에 조사하지 않았다.

## 3. 계획에 적용할 선택 조건

| 대안 | 비교할 이유 | 채택·재검토 조건 |
| --- | --- | --- |
| 일반 Python의 고정 흐름 | 호출 순서·도구 계약·실제 상태 변화를 드러내기 쉽다. 상태·재개 책임을 직접 관리해야 한다. | 작은 고정 흐름의 기본 비교안. 필요한 실패·권한·관찰을 설명할 수 있는지 본다. |
| LangGraph 같은 orchestration runtime | 상태 보존·중단/재개·사람 확인이 문제의 일부일 때 역할이 분명하다. 추상화와 새 API를 익히는 비용이 있다. | 해당 책임을 실제로 다룰 때 선택하고, 단순한 호출 연결만 필요하면 도입을 미룬다. |
| 제공된 agent 구조 | 빠른 전체 동작 관찰과 외부 코드 탐색에 쓸 수 있다. 제공 구조가 학습자의 직접 구현을 대신할 수 있다. | 현재 목표가 구조 탐색인지 내부 원리 구현인지 구별한다. 실행만으로 독립 구현을 인정하지 않는다. |

위 선택은 아직 운영 ROADMAP에 반영하지 않았다. 고정 흐름과 agent의 기능·품질·상태 결과 비교 역시 실제 실행 전에는 미확인이다. 이 보충 근거를 이유로 새 framework·추가 과정·유료 실행을 자동으로 의무화하지 않는다.
