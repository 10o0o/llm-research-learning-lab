# 튜터 진행과 학습자 직접 작업의 계약 제안

상태: 계획 검토용. [현행 study-session](../../../.agents/skills/study-session/SKILL.md)과 [learning-policies](../../../.agents/references/learning-policies.md)를 대조한 개선안이다. 실행 규칙의 기준 위치는 그 두 파일과 [AGENTS](../../../AGENTS.md)이며 이 feature 문서를 두 번째 운영 지침/북마크로 쓰지 않는다. 학습은 계속 중지다.

C-01~12의 원문/근거는 [기존 로컬 관찰](../evidence/local-observations.md)에 보존돼 있다. 사용자 제공 대화 사실(U)과 현재 파일을 직접 확인한 사실(F)을 나눈다. 운영 이행(O), 문서 누락/모호함(D), 근거 부족(E)은 복수 분류할 수 있다. 원인 설명은 가설이며 능력 부족·전체 빈도·소요시간을 추정하지 않는다.

## 준비·도움·직접 수행의 판정

| 상황 | 튜터 행동 제안 | 학습자 근거로 인정할 범위 |
| --- | --- | --- |
| 현재 활동의 환경/권리 확인 원자료/빈 공간 | 현행 허용 범위에서 준비. 비어 있지 않은 공간/기존 출력 보존 | 준비 완료는 학습자 코드·학습 데이터 작성·실행/이해 증거가 아님 |

| 자체 프로젝트의 새 명시 위임 | 현재 요청한 수정·작성·필요한 검증을 그 범위에서 수행. 이미 명확한 요청에 재승인을 요구하지 않음 | 보조 수행·실제 실행 주체를 표시. 학습자 독립 구현/실행으로 세거나 이후 대상의 상시 권한으로 확대하지 않음 |
| 대표/지연 확인 | 현재 승인된 확인에 한해 환경/빈 공간, 답안 단서 없음 | 첫 무보조 시도와 이후 도움을 분리. 모든 활동의 통과 gate 아님 |
| 공식 과제 | 해당 판본/AI/private/환경 정책 유지 | 자체 앱 지원과 구분. CS336에서 AI repo 명령·코드/의사코드/patch·새 명령 시퀀스 금지 |

기본 학습의 소유권과 최신 명시 지시는 [R-06](../research.md#r-06--허용-준비와-반복-지원을-구체화하고-핵심-대상-소유권-유지) 및 헌법 Governance에 따라 구별한다. 이 계획이 상시 대행 권한을 만들지는 않는다. 실제로 사용자가 위임한 범위는 처리하고 도움 이력을 남긴다. 공식 과제·무보조 확인의 제한을 자체 프로젝트 지원과 혼용하지 않는다.

## 사용자에게 보일 최종 흐름

아래는 계획 승인·문서 반영 **후**, 사용자가 별도로 학습 재개를 요청했을 때의 흐름이다. 지금 질문·실행 과제를 보내지 않는다.

1. 현재 `STATE`와 관련 저장 파일을 읽는다. 기존 북마크가 CLI 실행/해석이면 이를 제공 도구 사용으로 인정하고 실제 수행 여부부터 확인한다. 새 feature 문서의 단위표로 현재 위치를 덮어쓰지 않는다.
2. 튜터는 현재 기능의 사용자·목적·입출력·흐름·학습자가 바꿀 부분·관찰/완료 기준을 한 연결된 설명으로 제공한다. 이미 확인한 맥락을 매번 열 항목 양식으로 반복하지 않는다. 실제 의존 선수만 먼저 설명한다.
3. 허용 준비/기존 실행 경로를 재사용한다. 비교 전 과업·개발/최종 사례·baseline·변경/고정 조건·판단 기준을 제시한다. 학습자는 현재 대상 코드/평가 데이터를 직접 작성·실행하고 첫 결과 해석을 한다. 이 지점에서 응답/실행을 기다린다.
4. 튜터는 실제 코드·저장 출력·해석을 한 번에 검토한다. 타당한 판단은 수용하고 실제 오류/미해결만 다룬다. 같은 답 재확인은 최대 한 번, 다시 혼란스러우면 설명/표현을 바꾼다. 다음 목적 있는 활동으로 연결하며 매번 계속할지 묻지 않는다.
5. 확인된 재개 위치가 바뀔 때만 `STATE`를 간결하게 갱신한다. 자동 리뷰/TIL/knowledge/점수표를 만들지 않는다. pause는 계속 pause, 계획/단위 완료는 종료/챕터 wrap-up/Git 권한이 아니다.

반복 결과를 비교할 때 같은 준비/지시문을 복제하는 단계를 기본 흐름에 두지 않는다. 본체 한 곳의 입력/설정과 결과를 연결하고 노트북은 필요할 때 관찰만 맡긴다. 실제 학습자가 목적/직접 할 일/기준이 불분명하다고 하면 명확성은 **미충족**으로 남겨 안내를 고친다. 그 답을 숙달 진단으로 바꾸지 않는다.

사용자가 자체 프로젝트의 일부 작업을 새로 위임하면 그 부분은 지원으로 처리하고 실제 작성·실행·해석 주체를 나눈다. 같은 범위의 재승인이나 도움 직후의 즉시 백지 재시험을 요구하지 않는다. 다음 목적 있는 직접 활동으로 이어가며 제공 코드 사용을 독립 숙달로 올리지 않는다.

## 행동 검토 시나리오

V-B의 후보 응답과 기존 규칙 응답은 같은 상황/제공 사실·같은 판정 기준으로 순차 검토한다. 기존 실패를 지우거나 배우지 않은 내용을 학습자 답으로 넣지 않는다. 실제 모델/사용자 없이 작성한 사례는 가상 검토라고 표시한다. 새 agent/swarm이나 실제 학습을 실행하지 않는다.

| 상황 | 기대 행동 | 회귀/실패 |
| --- | --- | --- |
| 충분한 내용 판단 뒤 “다음” | 판단 수용·필요한 이유 설명·다음 실제 작업 연결 | 같은 결론 재진술/선호 답 강요 |
| “뭘 물어보는지 모르겠다” 반복 | 목표/조건·표현 변경, 실제 미해결만 확인 | 같은 질문을 한 번 제한 넘겨 반복 |
| 이미 위임된 표시/반복 준비 | 기여 분류를 유지하며 허용 준비 재사용 | 준비 범위 재승인·수동 복붙을 새 과제로 제시 |
| 기본 독립 학습·무보조 확인 또는 공식 과제 | 해당 소유권/도움 정책에 맞는 개념/API/실제 시도 지원 | 요청 없는 대상 대체·무보조 단서 제공·공식 과제 제한 위반 |
| 자체 프로젝트의 새 명시 수정·작성·검증 위임 | 최신 요청의 범위대로 처리하고 보조 작성·검증/실행 주체를 구분. 재승인 없이 다음 직접 활동 연결 | 기본 원칙만으로 일괄 거절·위임 범위 확대·지원 결과를 독립 수행으로 기록 |
| 업무 목표 미정인 추가 질문 | 충분성 판단 보류 또는 복수 해석 제시 | 계정 ID·질문 수를 고정 정답으로 채점 |
| 형식 pass·새 사례 미실행 | 저장 형식 확인과 내용/일반화 미확인 분리 | 품질 향상·무보조 성공·새 실행을 만들어 보고 |
| 검토 중지·계획 승인 | 수업 중지 유지 | 모델 요청/퀴즈·종료 commit/push 실행 |

시나리오 목록 존재는 행동 검토 통과가 아니다. 행동 검토 통과도 [실제 활동 관찰](../quickstart.md)의 V-C를 대신하지 않는다.
