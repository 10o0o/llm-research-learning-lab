# 전 8단위의 학습·산출물·평가 계약 제안

상태: 계획 검토용, 미승인·미반영. 현행 기준은 [ROADMAP](../../../ROADMAP.md)이며 [R-01~12](../research.md)는 변경 제안이다. 각 단위의 내부 작업은 한 목적의 입력→직접 작성→실행→첫 해석으로 연결한다. 셀 수·질문 수·파일 수·수업 시간을 완료 기준으로 삼지 않는다. 지금 새 과제·자료·코드·평가 정답을 만들거나 수업을 시작하지 않는다.

아래 직접 작업은 기본 학습과 그 수행 근거의 기준이다. 자체 프로젝트의 일부 작업을 사용자가 새로 명시 위임하면 [튜터 계약](tutoring-flow.md)의 지원 범위로 처리하고 독립 수행으로 세지 않는다. 공식 과제와 무보조 확인은 해당 활동의 제한을 유지한다.

## 전체 대응과 선택 순서

| 기존 단위 | 제안 상태 | 유지할 목적 | 조정·보류와 이유 |
| --- | --- | --- | --- |
| AX-01 | 조정 | 작은 AI 기능과 실제 평가 | 접수 정리의 목표·충분성, 반복 실행·도움 경계를 명확히 함. 현재 입력 검사를 재시작시키지 않음. |
| AX-02 | 조정 | 자료·검색·근거/기권의 실패 분해 | sparse baseline 하나부터, 추가 검색법 비교는 실제 실패/학습 질문에 조건부. 모든 검색법 순회 보류. |
| AX-03 | 조정 | 도구·상태·실패·권한 책임 | 고정 흐름 우선. framework/agent 비교의 자동 필수 해제, 상태/재개·동적 결정 필요 시 선택. |
| AX-04 | 조정 | 재현 가능한 서비스와 지원 설명 | 품질·입출력·오류·권리를 앞 단위부터 누적하고 서비스 경계/회귀를 여기서 강화. 인프라/새 UI 전체 트랙 보류. |
| RE-01 | 유지·작업 크기 명확화 | 실제 작은 모델 학습/검증/진단 | 기존 근거 재사용과 새 실행을 구별. 전체 기초 재수강 보류. 현재 착수 보류. |
| RE-02 | 유지·대체 관계 명확화 | 한 LM의 내부 구현/학습/재개 | 자체 LM 하나 또는 공식 A1. 둘 다 전체 구현하지 않음. 현재 착수 보류. |
| RE-03 | 조정 | 한 전문화의 통제 비교 | post-training/evaluation 우선 후보와 inference 대안 중 문제/자원에 맞는 하나. 두 갈래 병렬 필수 보류. 현재 착수 보류. |
| RE-04 | 유지·질문 출처 명확화 | 한 질문의 제한 재현·실험·보고 | 실제 관측/읽은 주장에 연결. 논문 quota·독창성/성능 보장·대규모 재현 의무 보류. 현재 착수 보류. |

AX의 권고 연결은 작은 기능→필요한 근거→필요한 조회/처리 흐름→서비스 신뢰성이다. 필요가 없는 도구를 넣으려고 문제를 바꾸지 않는다. AX-02/03의 조건부 항목을 수행하지 않으면 그 항목은 미수행 또는 근거 있는 제외로 남기며 **옛 계약 전체 완료로 소급 표시하지 않는다**. RE는 장기 깊이로 남기고 AX 시작/지원의 선수가 아니다. 새로운 문제·보류 과정 선택은 현행 범위 규칙을 따른다.

## AX-01 — 작은 AI 업무 기능

| 항목 | 제안 계약 |
| --- | --- |
| 판단·목적·두 목표 | **조정**. 학습용 접수 담당자의 문의 정리를 직접 구현·평가한다. 단기 업무 앱의 입력/모델/검증 경험, 장기 데이터/행동 평가의 출발점. 실제 업무 유용성은 미확인. |
| 입력·출력·흐름 | 권리 확인 본문/식별자→입력 확인→단순 기준과 모델 결과→형식 검사→원문 사실/추가 확인 필요의 내용 판단→결과/오류. 조직 정책·실제 계정 처리는 범위 밖. |
| 의미 있는 독립 행동 | 한 입력을 유용한 접수 초안과 판단까지 연결하는 기능 변경 하나를 작성·실행·해석. 현재 제공 CLI의 실행은 지원 도구 사용으로 분류하고 새 기능 구현과 혼합하지 않음. |
| 먼저 설명할 선수→의존 작업 | Python 자료/함수·JSON/예외는 입력/출력 처리 전에, HTTP 요청/오류·LLM 비결정성은 호출 전에, 과업/개발/최종 사례·반복/독립 차이는 첫 비교 전에 설명. 모든 문법 암기/HTTP 전 과정 요구 없음. |
| 작업 중 보강 | 실제 파싱/호출 오류의 해당 API·자료형·예외, 실제 응답 차이의 원문 근거/불확실성. 오류가 없으면 가설 퀴즈를 추가하지 않음. |
| 직접 작업·도움 | 새 대상 기능·평가 사례 구성·실행·첫 내용 해석은 학습자. 기존 검색/메시지/검사/CLI·표시 지원 이력 유지. 튜터는 권리 확인 원자료·환경·관련 없는 API 예·실제 시도 검토. |
| 최소 산출물 | 같은 실행 경로의 입력/응답/오류와 사전 기준, baseline 비교·실패/도움 설명. 자동평가 코드가 내용의 정답표를 대신하지 않음. 큰 앱/새 repo 불필요. |
| 사전 평가·완료 경계 | 아래 E-01을 실행 전 정한다. 정상/정보 부족/범위 밖과 형식/내용을 구별해 실제 비교하고 첫 해석. 새 사례·CLI 실제 모델 결과는 아직 미확인. 성능 향상 필수 아님. |
| 실패·미실행·반환 조건 | 목표가 불명확하면 충분성 채점 보류→목표를 짧게 명시. 모델 미접근은 미실행. 문제의 유용성이 여전히 설명되지 않으면 R-02 후보로 재검토; 과거 입력/출력 보존. |
| 연구·후속 연결 | 근거 없는 진술/질문 필요의 평가 문제가 AX-02 또는 RE의 모델 행동 질문으로 연결. 응답 형식 pass를 연구 성과로 바꾸지 않음. |
| 근거·현재 사실 | S-03/04/06, C-03~12, 현행 AX-01·study-session Teach and review. 노트북 1~5 셀·CLI 읽기 근거. 파일별 반영/검증은 추적표 U-AX-01. |

현재 `STATE`의 demo-003 실행/해석은 **현재 위치의 사실**로 보존한다. 이 계약이 새 다음 행동을 자동 선택하지 않는다. 학습 재개 후 실제 저장 근거를 본 뒤 큰 기능 작업과 연결하며 제공 CLI를 실행했다는 사실만으로 학습자 구현 완료를 선언하지 않는다.

## AX-02 — 데이터·검색·근거

| 항목 | 제안 계약 |
| --- | --- |
| 판단·목적·두 목표 | **조정**. 현재 서비스가 원문만으로 답할 수 없는 질문에서 근거를 찾고 답변/기권을 평가한다. 단기 자료 통합/검색, 장기 평가·오염/데이터 책임에 연결. |
| 입력·출력·흐름 | 권리 확인 corpus/metadata와 질의→정리/색인→검색→context→출처 있는 답변/기권→검색/종단 오류. 평가 질의/qrels를 corpus와 분리해 취급. |
| 의미 있는 독립 행동 | 작은 문서 모음에서 질의→근거→답변/기권까지 sparse baseline 하나를 직접 연결·실행·해석. 다음 비교는 관찰한 실패 또는 사전 학습 질문 하나로 dense/hybrid 중 하나만 선택. |
| 먼저 설명할 선수→의존 작업 | 문서/질의/정답 역할·중복/그룹·출처는 자료 구성 전, chunk/metadata는 색인 전, 벡터/내적/정규화·embedding은 dense 비교 전. 쓰지 않는 기법의 수학을 먼저 전부 요구하지 않음. |
| 작업 중 보강 | 실제 ranking·차원·중복/오래된 근거·context 잘림 실패에서 필요한 개념 보강. 통계는 작은 차이/의존 표본을 해석할 때 가정과 함께. |
| 직접 작업·도움 | 학습자가 정리/색인/검색/근거 구성·평가 질의/판단·실행/첫 해석. 튜터는 권리 확인 원문/환경·공식 API·실제 오류 검토. 평가 정답을 대신 생성하지 않음. |
| 최소 산출물 | baseline의 질의/검색 결과·출처·답변/기권·실패, 필요 시 비교 하나의 같은 조건 결과. 새 벡터 DB 플랫폼/전체 검색법 구현은 최소 요건 아님. |
| 사전 평가·완료 경계 | E-02. 근거 포함과 근거 사용/주장·누락/기권을 따로 판단. 다른 검색법을 안 했다면 미수행 또는 제외 이유를 밝힘; 단일 접근을 다중 비교로 포장하지 않음. |
| 실패·미실행·반환 조건 | corpus 자체에 근거 없음과 검색 누락을 나눔. 권리/장치/embedding 미해결은 해당 비교 미실행. 적절한 corpus가 없으면 현재 사실 정리 범위로 제한하고 문제/자료 재검토. |
| 연구·후속 연결 | 검색 실패와 생성 실패의 분해, 데이터 중복/평가 오염이 후속 행동/데이터 연구 질문으로 연결. |
| 근거·현재 사실 | S-02/04/06, C-03/11/12, 현행 AX-02·learning-policies Evaluation. 해당 학습자 구현·실행 근거는 이번 검토 범위에 없음. U-AX-02에서 추적. |

## AX-03 — 도구와 제한된 workflow

| 항목 | 제안 계약 |
| --- | --- |
| 판단·목적·두 목표 | **조정**. 처리에 실제 필요한 로컬 조회/모의 상태 도구를 연결해 성공 보고와 실제 결과를 대조. 단기 API/업무 통합, 장기 agent 평가·실패 분석에 연결. |
| 입력·출력·흐름 | 문의/근거·현재 모의 상태→도구 계약 확인→고정 분기→결과/오류→필요한 사람 확인→허용 로컬 결과/최종 상태. 외부 업무 실행 없음. |
| 의미 있는 독립 행동 | 유용한 로컬 조회 또는 처리 초안 흐름 하나의 정상/실패를 직접 구현·실행·해석. 상태/재개 필요 시 framework 하나, 모델 주도 선택의 가설이 있으면 같은 과업의 단일 agent 비교. |
| 먼저 설명할 선수→의존 작업 | 함수/API·필요 시 SQL 계약은 도구 전, 상태·부작용·멱등성·권한/사람 확인은 모의 변경 전, workflow/agent 차이와 step 종료는 비교 전. |
| 작업 중 보강 | timeout/retry·중복·중단/재개·주입/권한 혼선이 실제로 드러난 부분만 보강. MCP는 실제 표준화 필요가 생길 때 후보. |
| 직접 작업·도움 | 학습자가 도구·분기·실패/상태 확인·비교/해석. 튜터는 허용된 모의 환경·공식 개념/API·코드/출력 검토. 제공 agent 실행을 직접 구현으로 인정하지 않음. |
| 최소 산출물 | 한 도구의 입력/결과/오류 계약과 trace·전후 실제 모의 상태/권한 대조. 비교했다면 동일 과업 결과, 제외했다면 이유/재검토 조건. |
| 사전 평가·완료 경계 | E-03. 정상·도구 실패·중복·거절·단계 제한의 실제 상태를 확인. framework 사용 여부가 아니라 책임과 실패 진단을 기준으로 삼는 변경안. |
| 실패·미실행·반환 조건 | 성공 메시지와 상태가 다르면 실패. 도구/모델 접근 불가면 미실행. 동적 선택이 유용하지 않으면 고정 흐름 유지, 필요한 재개 책임이 없으면 LangGraph 도입 보류. |
| 연구·후속 연결 | 도구 선택/상태/권한 실패를 분해한 행동 평가 질문으로 연결. 이것만으로 모델 내부 연구를 수행한 것은 아님. |
| 근거·현재 사실 | S-04/08, C-03/06/08, 현행 AX-03의 고정 LangGraph/비교와 변경 제안의 차이를 명시. 구현/성능 미확인. U-AX-03에서 추적. |

## AX-04 — 서비스 품질·지원 근거

| 항목 | 제안 계약 |
| --- | --- |
| 판단·목적·두 목표 | **조정**. 같은 서비스의 요청/저장/오류·재현/회귀를 강화한다. 단기 설명 가능한 서비스·지원 근거, 장기 실험/서빙의 재현·관측 책임에 연결. |
| 입력·출력·흐름 | 요청·자료/모델 설정·저장 상태→검증/권한→AI/검색/도구→저장/응답→로그/평가→회귀·변경 판단. |
| 의미 있는 독립 행동 | 현재 기능 하나를 API/저장 경계와 정상/오류 응답으로 연결해 회귀를 직접 확인한다. 이후 재현 안내/최소 UX·로컬 컨테이너가 필요한 만큼 확장. |
| 먼저 설명할 선수→의존 작업 | HTTP·입출력·상태/테스트는 API 전, PII/비밀정보와 권한은 저장/로그 전, latency·usage·비용의 측정 단위와 외부 조건은 측정 전. |
| 작업 중 보강 | 실제 요청 간 누수·동시성·timeout·회귀·비용/지연 문제를 근거로 해당 범위 보강. 새 UI/범용 인프라 과정을 시작하지 않음. |
