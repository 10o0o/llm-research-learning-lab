# 계획 검증과 승인 후 확인 안내

이 문서는 [plan](plan.md)의 검증 안내다. 학습자 구현 코드·새 평가 정답·과제 실행 명령은 제공하지 않는다. V-A(문서/보존), V-B(운영 응답 행동), V-C(실제 재개 관찰)를 구별한다. **지금은 V-A만 수행하며 학습은 중지다.** 이번 실제 결과는 [plan-validation](evidence/plan-validation.md)에 기록한다.

## 전제와 준비

- 기존 `main`과 동일 feature를 사용한다. 기존 STATE/설정·lock/미추적 실습·staged 내용을 보존한다. 새 run/branch/repo·설치·download·모델/학습자 코드 실행·게시·stage/commit/push/reset/stash는 하지 않는다.
- 명세 승인은 최신 사용자 인계로 완료다. 명세 38요구·기존 체크리스트/evidence는 보존하며 계획 승인 질문을 명세 승인 질문으로 되돌리지 않는다.
- 지금 필요한 준비는 저장소 루트와 문서 읽기 도구뿐이다. 표준 Python 검사는 기존 interpreter로 수행한다. 새 환경·package를 설치할 필요가 없다.
- 엔진 상태 확인은 상위 도우미가 맡는다. 이 command 안에서 workflow check/run/resume이나 엔진 파일/로그 직접 수정을 하지 않는다.

## V-A — 지금 수행할 문서와 보존 검증

저장소 루트에서 다음을 실행할 수 있다. 아래 Python은 계획 문서의 최소 형태/공백 확인이며 전체 검증을 대체하지 않는다. 새 실습을 만들거나 실행하지 않는다.

```bash
python3 - <<'PY'
from pathlib import Path
import re
feature = Path('specs/002-learning-method-audit')
for name in ('plan.md', 'research.md', 'data-model.md', 'quickstart.md',
             'contracts/unit-audit.md', 'contracts/tutoring-flow.md'):
    text = (feature / name).read_text()
    assert text.strip() and text.endswith('\n'), name
    assert all(line == line.rstrip() for line in text.splitlines()), name
spec = (feature / 'spec.md').read_text()
assert len(re.findall(r'^- \*\*FR-\d{3}\*\*:', spec, re.M)) == 38
assert not (feature / 'tasks.md').exists()
print('PASS: plan artifact presence, whitespace, 38 source requirements; no tasks')
PY
git diff --check
git status --short --branch
```

`git diff --check`는 미추적 문서를 모두 검사하지 않으므로 새 문서의 공백/링크/표는 따로 확인해야 한다. 통과한 문구 수를 교육 효과 점수로 보고하지 않는다.

### 후속 운영 파일을 반영한 뒤의 회귀 확인

다음 명령은 **계획 승인 뒤 실제 운영 문서/검사를 변경했을 때** 저장소 루트에서 수행할 검사다. 이번 문서 계획의 V-A 통과를 뜻하지 않으며, 현재 이 단계에서 실행한 명령도 아니다. 기존 환경만 사용하고 설치가 필요하면 그 한계를 보고한다.

```bash
uv run --frozen pytest -q tests .agents/skills
uv lock --check
git diff --check
```

R-11의 테스트 수정은 실제 STATE를 옛 문구로 되돌리는 방식이 아니다. 기존 테스트의 보호/과제/준비·소유권/종료 규칙을 유지하면서 후속 단위·평가/해석 중심의 타당한 북마크를 검사할 수 있게 한다. 잘못된 단위·두 다음 행동·사적 정보가 거절되는 부정 사례도 확인한다. 보호 대상 때문에 파일을 읽는 기존 검사는 후속 실행 시의 허용 범위와 대조하고 지금 금지된 영역에 들어가기 위해 실행하지 않는다.

## V-B — 승인 후 운영 응답의 행동 검토

현재 스킬에 있는 [기존 검토 방법](../../.agents/skills/study-session/references/tutor-cases.md)과 [새 시나리오](contracts/tutoring-flow.md#행동-검토-시나리오)를 대조한다. 이 단계에서는 새 에이전트·외부 유료 호출·실제 학습을 시작하지 않는다. 후속 검토도 한 작성자가 순차 수행하고 실제 평가 실행이 없으면 설계/수동 검토로 표시한다.

1. 같은 제공 사실·사용자 반응·과업/판정 기준으로 기존 지침과 후보 지침의 응답을 비교한다. 환경/모델/설정이 다르면 비교 제한으로 표시한다. 기준은 응답을 본 뒤 유리하게 바꾸지 않는다.
2. 충분한 답 수용, 반복 혼란의 표현 변경, 준비 복사/재승인 방지, 기본 독립 학습·공식 과제의 제한, 자체 프로젝트의 새 명시 위임, 목적 미정의 충분성, 형식/내용/미실행, pause 유지의 8상황을 검토한다.
3. 검사 대상의 실제 응답과 판정 이유를 대조한다. 사람이 대신 쓴 모범 응답이나 성공한 사례만으로 응답 개선을 입증하지 않는다. 실패/접근 불가/미실행은 각각 남긴다.
4. 가상 검토 통과는 운영 규칙 이행의 제한된 근거다. 실제 사용자 불편 감소·독립 구현/실행·장기 기억/취업 효과는 미확인으로 둔다.

새 자동 harness·agent swarm·학습자 점수표/진도 기록을 이 계획으로 만들지 않는다. 원래 사례의 지정된 비교 조건을 바꿨다면 동일 비교가 아님을 보고한다.

## V-C — 학습 재개 뒤 실제 활동 한 단위 이상의 수동 관찰

필수 전제는 **사용자의 별도 학습 재개 요청**이다. 계획 승인/문서 반영은 재개 요청이 아니다. 현재 STATE의 북마크와 저장 근거부터 확인하고, 튜터가 과업/평가·최소 선수를 제공한 뒤 학습자가 직접 작업한다. 지금은 아래 관찰 전부 미수행이다.

| 관점 | 관찰할 실제 행동/근거 | 충족·실패·미수행 판단 |
| --- | --- | --- |
| 1. 기계적 복붙·화면 이동 | 같은 준비/지시문/요청 코드를 옮겨야 실행되는지, 입력/설정만 바꿔 결과/오류를 찾을 수 있는지 | 불필요한 재복사 필수 단계가 없거나 남기는 구체 이유가 있어야 함. 과거 값 없으면 개선율 금지. 새 기능 작성·필요한 디버깅을 준비 반복으로 세지 않음. |
| 2. 목적 명확성 | 시작 전에 현재 문제·본인이 바꿀 기능·입출력·관찰/완료 기준을 안내받아 실제 작업할 수 있는지 | 학습자가 불명확하다고 하면 미충족, 설명을 조정. 확인을 위해 선호 문장 암기/재진술 시험을 추가하지 않음. |
| 3. 학습자 직접 구현 | 현재 대상의 새 코드/변경·평가 사례를 누가 작성했는지, 제공/복구 도구와 무엇이 다른지 | 제공 CLI 실행/파일 이동만으로 직접 구현 충족 처리 금지. 학습자가 아직 작성 안 했으면 미수행/도움으로 남김. |
| 4. 실행·첫 해석 | 학습자가 저장한 실제 코드/출력과 첫 판단 | 학습자 실행/저장 없음은 미확인. 명시 위임으로 튜터가 수행한 검증은 지원 수행이며 이 관찰의 학습자 실행을 대신하지 않음. 모의 검사·기존 출력과 구별. |
| 5. 사전 평가·실제 피드백 | 과업·사례/반복·개발/최종·baseline·변경/고정 조건을 실행 전에 정하고 실제 출력/해석에 피드백했는지 | 형식과 사실/중복 질문/업무 필요·검색/도구 상태를 따로 봄. 타당한 충분성 수용, 사후 기준 변경 공개. 실제 미개선도 유효, 미실행과 다름. |
| 6. 기여·재현 설명 | 자기 변경/도움·원출처/권리·실행 환경/조건·결과/실패와 미검증 설명 | 제공/팀 코드나 로컬 실행을 독립 구현/운영으로 포장하면 실패. 새 커널/다른 환경 미실행이면 재현 확인으로 쓰지 않음. |

결과는 기존 대화/허용된 산출물에 근거해 짧게 검토한다. 새 추적 DB·자동 보고서·날짜별 TIL·knowledge·진도 체크리스트를 만들지 않는다. 실제 다음 행동이 바뀌면 STATE에 현재 근거/재확인·다음 하나만 남긴다. 지연 회상은 별도 요청/계획된 대표 확인과 실제 시기에 근거하며 여기서 자동 수행하지 않는다.

### 유지·수정·기각

- 목적 있는 직접 작업/사전 평가/첫 해석을 관찰하고 준비 반복이 줄어드는 방향이면 그 범위의 근거만 보고한다. 사전 baseline이 없으면 감소 정도를 수치로 주장하지 않는다.
- 반복 복사·질문 혼란이 남거나 새 구조가 첫 작업을 막으면 안내/단위를 고친다. T-03의 중복/커널 부담이 더 크면 T-02로 단순화하거나 해당 관찰을 T-01에 제한한다.
- 현재 문의의 목적·충분성을 명확히 해도 유용성이 설명되지 않으면 R-02의 대체 문제를 검토한다. 원본/기여/실패를 보존하고 새 범위는 기존 선택 규칙을 따른다.
- 실행 안 함·관찰 기회 없음은 미수행이다. 실행 후 나쁜 결과는 부정 결과다. 어떤 경우에도 효과 성공·숙달·취업으로 자동 처리하지 않는다.

## 최종 보고와 경계

지금 보고는 생성한 계획/설계·실제 문서 검증·보존 결과·남은 실제 관찰·계획 승인 대기까지다. command 안의 plan running은 반환 뒤 엔진 paused의 확인이 아니다. 상위 도우미가 같은 Run의 `plan: completed`와 `review-plan` 대기/paused 여부를 확인한다. 이 command는 그 상태를 만들기 위해 엔진 파일을 직접 수정하지 않는다.
