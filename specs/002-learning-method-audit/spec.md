# 기능 명세: 전체 학습 경로와 실제 학습 방식의 근거 기반 재감사

**작업 브랜치**: `main` — 브랜치 생성·전환 없음

**작성일**: 2026-10-21

**상태**: Approved — 사용자의 “진행해”로 명세 승인. 계획 작성은 허용됐으며 계획 승인·작업 목록·운영 반영은 미수행

**입력**: “Spec Kit을 사용해서 ROADMAP과 목표를 전수 검토하고 학습 방법이 올바른지 검토·개선해 달라. 실제 유명 실무 교육과 대학의 자료·학습 방식, 사용자의 불만과 실제 진행의 차이, 결과물을 지속 발전시키고 포트폴리오로 활용할 저장소 전략을 조사해 달라.” 단기 AX/AI 애플리케이션 취업 준비와 장기 LLM Research Engineer 목표를 유지하면서 기존 설계와 운영을 독립적으로 재검토한다.

이 feature는 완료된 [001 명세](../001-employment-project-curriculum/spec.md)의 후속 재감사다. 기존 결론을 정당화하거나 노트북을 스크립트로 옮기는 작업만으로 축소하지 않는다. 이 문서는 무엇을 왜 검토하고 어떤 근거로 개선을 판단할지 정한다. 실습 방식·저장소·교육과정의 미검증 대안은 채택 사실이 아니다.

명세 구체화를 위한 [초기 재감사와 개선 후보](evidence/initial-review.md), [현재 문서·산출물 관찰](evidence/local-observations.md), [공식 교육 자료 초기 조사](evidence/official-education-sources.md)를 작성했다. 초기 재감사는 전 8단위·불만·실습·저장소 대안을 비교한 검토 자료다. 제안의 채택·운영 반영·개선 효과·학습자 수행의 완료 보고는 아니다.

### 명세 승인 후 계획 단계 인계

- 명세 승인 질문에 사용자가 “진행해”라고 답했다. 같은 공식 Run `94c571a9`를 재개해 `speckit-plan`을 수행하고 `review-plan`에서 다시 검토받는다. 명세 작성 시의 중지 지시는 명세 승인 전 경계였으며 현재 계획 작성을 금지하는 지시가 아니다.
- 기존 조사와 초기 검토를 바탕으로 유지·변경·제외 결정을 구체화한다. 전체 8단위의 작업·선수·산출물·평가, 불만별 개선과 검증, 실습 3안의 14관점, 저장소 5전략의 9관리 항목을 비교해 계획에 연결한다. 기본 문의 문제의 적합성과 대안도 실제 근거로 판단한다.
- 계획 산출물은 이 feature의 `plan.md`, `research.md`, `data-model.md`, 필요한 `contracts/`, `quickstart.md`다. 데이터 모델은 검토 항목의 문서상 관계이며 새 학습 DB나 앱이 아니다. 운영 파일별 변경 내용·보존·검증 방법을 계획하되 아직 적용하지 않는다.
- `.specify/memory/constitution.md`, ROADMAP·STATE·AGENTS·스킬·운영 검사·실습·기존 feature를 보존한다. 새 저장소·수업·모델 실행·과제 clone·환경 설치·stage·commit·push는 수행하지 않는다. 계획 승인 후의 반영과 학습 재개 후 실제 효과 검증을 구별한다.
- 추가 에이전트·swarm을 만들지 않고 조사·설계는 순차 수행한다. 상위 도우미가 정상 재개한 실행 안에서 중첩 `run`을 시작하거나 어댑터 내부 재검사 오류를 전체 실패로 판단하지 않는다. `setup-plan.sh --json`과 공식 plan 절차를 수행한 뒤 계획 승인 경계에서 멈춘다.

## 사용자 시나리오와 검증 *(필수)*

### 사용자 시나리오 1 — 전체 경로의 필요성과 직접 할 일을 판단한다 (우선순위: P1)

학습자는 AX-01~04와 RE-01~04 각각이 두 목표에 왜 필요한지, 무엇을 직접 만들어 어떤 결과로 판단할지 확인한다. 기존 순서·기술 선택도 재검토하되 시간·기량이 미확인인 상태에서 완성 시점이나 취업을 약속하지 않는다.

**우선순위 이유**: 첫 활동의 불편만 고쳐 장기 경로의 과잉·누락·중복을 그대로 두는 검토를 방지한다.

**독립 검증**: 다른 개선안의 채택 없이도 8개 단위의 현행 계약과 유지/조정/보류 제안, 이유·근거·미확인을 대조할 수 있다.

**인수 시나리오**:

1. **조건** 현행 8개 단위가 존재할 때, **행동** 재감사 결과를 읽으면, **결과** 각 단위의 목표 연결·최소 선수·실제 작업·독립 행동·산출물·완료 근거·평가/실패·연구 연결과 제안 상태를 찾을 수 있다.
2. **조건** 기본 서비스의 문제 적합성이나 기술·순서·비교 실험의 필요성이 불명확할 때, **행동** 선택을 검토하면, **결과** 현행 채택 사실과 새 제안을 구별하고 유지·단순화·대체·보류의 이유와 재검토 조건을 비교한다. 기존 설계의 존재가 유지 근거를 대신하지 않는다.
3. **조건** 장기 모델·연구 작업의 선수나 자원이 부족할 때, **행동** 단기 경로와 연결하면, **결과** 관련 최소 선수와 미수행 범위만 밝힌다. 전체 수학·대학 과제·RE 완성을 첫 AX 활동이나 지원의 관문으로 복원하지 않는다.
4. **조건** 작은 기능에 실제 근거가 있을 때, **행동** 지원 자료 활용을 검토하면, **결과** 조기 공고 비교·지속 발전할 주 포트폴리오·장기 연구 산출물을 구별한다. 지원 적합성·취업을 보장하지 않는다.

### 사용자 시나리오 2 — 교육 기관의 실제 운영을 비교한다 (우선순위: P1)

학습자는 기관 이름·목차 대신 실제 과제·lab·프로젝트·평가·피드백·도움 정책을 읽은 비교를 받는다. 공식 원문의 관찰과 우리 상황에 적용한 해석을 나눠 선택·제외 이유를 판단한다.

**우선순위 이유**: 이전 조사 제목의 반복이나 기관의 명성으로 현재 방식을 정당화하는 일을 방지한다.

**독립 검증**: 실무 교육 3곳 이상·대학 강의 3개 이상의 출처 카드에서 판본·구간·실제 요구·접근 한계와 적용 해석을 추적할 수 있다.

**인수 시나리오**:

1. **조건** 공식 자료를 조사할 때, **행동** 출처를 검토하면, **결과** URL·판본/개정 여부·조회일·구간·관찰 사실·적용 해석·한계가 구별된다. 미확인을 추측으로 채우지 않는다.
2. **조건** 노트북 lab·완성 walkthrough·직접 구현 과제·단계적 프로젝트가 있을 때, **행동** 방식을 비교하면, **결과** 제공 코드와 학습자 작업, 평가/피드백 접근 권한, 선수·장치/계정/비용 조건을 나눠 설명한다.
3. **조건** 최신 소개와 과거 과제 지침이 다른 판본을 가리킬 때, **행동** 비교에 사용하면, **결과** 판본을 분리하고 확인되지 않은 2026판을 만들지 않는다. 접근 실패·정책 미기재도 표시한다.
4. **조건** 기관이 포트폴리오·취업·도구의 장점을 홍보할 때, **행동** 근거로 사용하면, **결과** 운영 사실과 효과 주장을 구별한다. 개인의 성과나 인과 효과로 확대하지 않는다.

### 사용자 시나리오 3 — 불만과 실제 진행을 연결해 튜터 운영을 개선한다 (우선순위: P1)

학습자는 반복 오류·불명확한 질문·출력 가독성·복붙 부담·진행 정체를 관찰 근거와 함께 검토받는다. 능력 부족으로 단정하거나 모든 대상 코드를 대신 작성하는 방식으로 해결하지 않는다.

**우선순위 이유**: 올바른 문구가 있는 문서와 불편했던 실제 운영 사이의 차이가 재감사의 핵심이다.

**독립 검증**: 요청의 불만·최근 판단 각각에서 불만→실제 진행→원인 가설/불확실성→개선 가설→검증 행동과 문서 위반/보완 필요를 찾을 수 있다.

**인수 시나리오**:

1. **조건** “너가 알아서 하고 진도 나가고싶다”·일부 코드 작성 위임 뒤 지원 코드가 있을 때, **행동** 근거를 분류하면, **결과** 명시 위임된 지원·직접 작성·직접 실행·첫 해석·무보조 확인을 나눈다. 과거 도움을 지우거나 새 독립 성공으로 올리지 않는다.
2. **조건** “뭘 물어보는거야?”·“다시 질문해”라는 반응이 있을 때, **행동** 원인을 검토하면, **결과** 목적·조건·질문 단위·표현의 문제와 실제 선수 공백을 구별한다. 충분한 답을 선호 문구로 반복시키지 않는다.
3. **조건** 추가 확인 정보를 평가하지만 업무 목표·허용 절차가 불명확할 때, **행동** 답을 판단하면, **결과** 계정 ID 등을 유일한 정답으로 강요하지 않고 판단 기준·대안 해석을 먼저 확인한다. 형식 검사와 내용 타당성은 별개다.
4. **조건** 저장 근거에는 일부 실행만 있고 새 사례 실행은 없을 때, **행동** 개선 여부를 보고하면, **결과** 확인한 지시문·저장 출력, 제안한 확인 기준과 실제 추가 실행·평가의 미확인을 나눈다.

### 사용자 시나리오 4 — 실습 도구를 목적과 반복 작업에 맞춰 비교한다 (우선순위: P1)

학습자는 노트북 중심, 모듈/프로젝트 중심, 본체와 선택적 관찰 노트북의 조합을 비교한다. 셀별 복붙·질문 쪼개기를 도구의 필연적 특성으로 판단하지 않는다.

**우선순위 이유**: 확장자만 바꾸면 소유권·질문 품질·평가 부재가 그대로 남을 수 있다.

**독립 검증**: 같은 목표·작업 흐름에서 세 대안의 장단점·전환 비용·직접 작업·채택 조건을 비교할 수 있다. 기존 실습의 이동·실행은 필요하지 않다.

**인수 시나리오**:

1. **조건** 실습 방식을 비교할 때, **행동** 비교표를 읽으면, **결과** 세 대안 모두에 FR-023의 14관점을 적용하고 장치별 미측정은 표시한다.
2. **조건** 본체와 관찰 공간을 함께 두는 안을 검토할 때, **행동** 유지 비용을 판단하면, **결과** 중복 코드·지시문/설정 불일치·오래된 출력의 위험과 기준 구현 유지 조건이 제시된다. 혼합안의 채택은 미리 확정하지 않는다.
3. **조건** 거대한 골격·자동 검증 체계부터 준비하는 안이 있을 때, **행동** 첫 유용한 결과까지의 부담을 비교하면, **결과** 준비 비용·학습자 기여 감소·현재 필요한 최소 검증과 후속으로 미룰 조건을 제안한다.

### 사용자 시나리오 5 — 결과물을 지속 발전시키고 기여를 설명한다 (우선순위: P2)

학습자는 lab 내부, 별도 서비스 저장소 하나의 지속 발전, 서로 다른 문제의 소수 프로젝트, 단계마다 새 저장소, 연구 실험의 별도 저장소를 비교한다. 결과·실패·출처·기여와 재현을 보존하며 분리 시점을 판단한다.

**우선순위 이유**: 결과를 설명 가능한 산출물로 연결하되 저장소 수 자체를 목표로 만들지 않는다.

**독립 검증**: 다섯 전략의 분리/유지 조건·산출물 관리 제안에서 공개 전 준비·기여·재현의 경계를 확인할 수 있다. 저장소 생성·게시·배포 없이 검토한다.

**인수 시나리오**:

1. **조건** 서비스 기능이 늘거나 연구 질문이 독립할 때, **행동** 저장소 전략을 검토하면, **결과** 독립성·환경·권리·공개 범위·평가·기여·유지 비용에 따른 조건이 있다. 단위마다 새 저장소를 자동 생성하지 않는다.
2. **조건** 강의·튜터·팀·기존 사내비 작업을 참고했을 때, **행동** 포트폴리오로 설명하면, **결과** 원출처·권리·직접 기여·변경과 실패를 구별한다. 저장소 수·튜터 기능을 독립 역량으로 세지 않는다.
3. **조건** 특정 과정이 공개·프로젝트 재사용을 제한할 때, **행동** 지속 발전 전략에 적용하면, **결과** 과정별 제출 규칙과 독립 프로젝트를 구별한다. 공식 과제 답안을 공개 포트폴리오로 옮기지 않는다.

### 사용자 시나리오 6 — 검토·실제 검증·승인을 구별한다 (우선순위: P1)

학습자는 개선안의 채택·수정·기각을 판단할 관찰 기준을 확인하고 명세와 계획을 각각 승인한다. 문서·가상 응답 검사와 실제 학습 활동의 결과를 구별한다.

**우선순위 이유**: 문구를 고쳐 검사만 통과한 상태를 교육적 개선 완료로 보고하지 않는다.

**독립 검증**: 요구·출처·제안·검증 행동을 대조하고 승인 전 변경 범위·학습 중지 유지를 확인할 수 있다.

**인수 시나리오**:

1. **조건** 명세·품질 검토가 끝났을 때, **행동** 상태를 보고하면, **결과** `review-spec`에서 기다린다. 요청·체크리스트 통과는 명세/계획 승인이 아니다.
2. **조건** 향후 승인된 학습 활동에서 개선을 관찰할 때, **행동** 같은 목적의 작업 전후를 비교하면, **결과** 복붙·이동, 목적·직접 구현·실행·첫 해석, 사전 기준·실제 피드백을 본다. 기존 기준값이 없으면 개선율을 만들지 않는다.
3. **조건** 문서·링크·가상 응답만 검사했을 때, **행동** 결과를 보고하면, **결과** 구조·운영 응답의 검토로만 표시한다. 실제 학습 효과·새 커널 재현·장기 기억·취업·운영은 미확인으로 둔다.
4. **조건** 실행 도우미가 시작되지 않을 때, **행동** 가능한 명세 작업을 수행하면, **결과** 실제 오류·스킬 수행 범위를 밝힌다. 없는 Run ID·엔진 `paused`·승인·완료 상태를 만들지 않는다.
