# 외부 실습 연결

이 허브는 따라갈 자료와 재개 위치를 관리한다. 실제 코드·실행 결과는 학습자 소유의
외부 저장소에 둔다. 현재 선택과 작업 위치는 [STATE](../STATE.md)가 기준이다.

## 1. 실습 공간을 고른다

| 선택한 학습 형태 | 시작 방법 |
|---|---|
| 공식 starter·테스트가 있는 과제 | 해당 판본의 starter와 환경을 사용하고 미완성 부분을 직접 구현한다. |
| 영상·책을 보며 처음부터 구현 | 자기 실습 저장소의 작은 파일이나 notebook에서 시작한다. |
| 기존 프로젝트에 적용 | 이미 작업 중인 저장소의 관련 기능을 이어간다. |
| 강의 내용을 자기 데이터로 확장 | 해당 과정의 프로젝트 지침을 읽고 사용할 데이터·실습 공간을 정한다. 이해한 자기 코드를 재사용하되 공식 실습과 적용 범위를 표시한다. |

강의 또는 지속 프로젝트 단위로 묶는다. 한 개념마다 새 저장소를 만들지 않는다.
공식 저장소는 출처이고, 자신의 실습 저장소는 직접 수행하는 공간이다.
완성된 강사 코드의 복사·실행만으로 독립 구현을 기록하지 않는다.

실습 공간이 이미 있으면 그 URL이나 로컬 위치부터 연결한다. 새 공간이 필요하면
선택한 자료와 공개 정책에 맞춰 마련한다. 실제 생성 전에는 예시 이름이나 URL을
존재하는 저장소로 기록하지 않는다. 공식 과제 답안의 공개 여부와 AI 사용 범위는
[과정별 정책](../.agents/references/official-course-policies.md)과 해당 원문에서 확인한다.
각 실습은 자체 의존성·Python 버전·커널을 사용한다.

## 2. 현재 범위를 실습 세션에 전달한다

허브의 AGENTS와 스킬이 다른 저장소에서 자동으로 적용된다고 가정하지 않는다.
실습 공간의 기존 지침과 공식 과제 정책을 함께 읽는다.
아래 내용은 에이전트가 확인된 STATE에서 채운다. 학습자에게 별도 양식 작성을 요구하지 않는다.

- 현재 공식 자료와 정확한 구간
- 자기 프로젝트를 수행하는 세션이면 선택한 적용 범위와 참고할 공식 구간
- 이번에 직접 구현하거나 확인할 부분
- 실제 실습 저장소와 파일·폴더
- 막힌 부분과 다음 행동
- 허브 STATE의 위치와 접근 가능 여부

실습 공간에서 반복적으로 AI를 사용한다면 다음 짧은 규칙을 그 공간의 지침에
추가할 수 있다. 기존 지침 전체를 덮어쓰거나 모든 업무 공간에 전역 적용하지 않는다.

```markdown
## 학습 도움
선택한 강의·과제와 현재 범위를 기준으로 돕는다.
핵심 구현, 실행, 결과의 첫 해석은 학습자가 수행한다.
요청 없이 완성 코드나 답이 포함된 골격을 먼저 작성하지 않는다.
개념·문법·API 질문에는 충분히 설명하고, 질문만 반복하지 않는다.
학습자가 작성한 코드·출력부터 검토하고 작은 확인 방법을 제안한다.
현재 작업에 필요한 수학부터 설명하며 새 과정·과제를 임의로 추가하지 않는다.
공식 과제의 더 엄격한 도움·공개 정책을 따른다.
진도의 원본은 학습 허브의 STATE.md이며, 확인된 위치와 미완료를 보존한다.
의미 있는 진행과 종료·중단에는 허브의 STATE를 갱신하고 다시 읽어 저장을 확인한다.
허브에 접근할 수 없으면 수행·남은 문제·다음 행동과 코드 위치를 반환한다.
이 전달문을 STATE 저장 완료라고 말하지 않으며, 직접 확인과 학습자 보고를 구분한다.
```

이 규칙은 실제로 사용할 실습 공간에만 적용한다.
현재 허브 정리만으로 외부 저장소가 생성되거나 지침이 설치된 것은 아니다.

## 3. 실습하고 필요한 도움을 받는다

공식 자료의 해당 부분을 읽거나 본 뒤, 요구하는 작은 단위를 직접 수행한다.
개념 질문에는 설명을 받고, 작성한 코드나 결과가 있으면 그것을 놓고 리뷰한다.
이미 이해한 코드·환경은 재사용한다. 매번 전체를 다시 만들거나 종료 퀴즈를 치를 필요는 없다.
상세 설명과 실험 결과는 해당 실습의 파일 또는 README에 필요한 만큼 남긴다.

### 프로젝트와 실험의 근거

공식 강의·과제의 기본 흐름을 유지하며 자기 문제로 적용한다. 에이전트는
[자료별 공식 범위와 확장](../CURRICULUM.md#자기-데이터의-첫-프로젝트)을 구분해 안내하고,
프로젝트의 핵심 설계·구현·실행·첫 해석은 학습자가 맡는다. 실제 필요한 기초부터 설명받고
같은 코드·결과로 돌아온다. 일정과 후속 실험 후보는 [ROADMAP](../ROADMAP.md#첫-집중-구간-12주)을 따른다.

외부 레포의 기존 README·실험 기록에 다음 근거를 연결한다. 별도 계획서나 매 세션 보고 양식을
학습자에게 요구하지 않으며, 에이전트는 제공된 결과를 바탕으로 정리를 도울 수 있다.

| 근거 | 실제로 남길 내용 |
|---|---|
| 문제·데이터 | 사용자·질문·유용한 답변의 기준, 출처·이용 조건, 수집·갱신 방법 |
| 실행·재현 | 준비·실행 방법과 필요한 설정, 사용한 버전·환경, 주요 경로 확인 결과, 데모 |
| 평가·비교 | 기대 근거가 있는 질문, 비교 조건과 기준선·후보 결과, 사람이 직접 검토한 답변 |
| 실패·판단 | 검색 실패·잘못된 근거·근거 없는 답변 등의 구분, 변경 이유, 개선되지 않은 결과와 한계 |
| 운영·성능 | 측정 구간·장비·반복 조건, 지연·처리량·메모리 또는 호출 비용·오류·피드백 등 선택한 작업의 지표 |
| 수행·도움 | 학습자가 직접 한 일과 주요 AI·다른 사람의 도움, 아직 미실행·미완료인 범위 |

첫 RAG 평가는 직접 검토한 30~50문항에서 작게 시작할 수 있다. 질문 수 자체를 충분성이나
수료 기준으로 삼지 않는다. 기대 근거를 남기고 조정용과 최종 확인용을 구분한다.
최종 확인용 결과를 보고 반복 튜닝했다면 독립적인 최종 평가로 부르지 않는다.
LLM 채점 일부는 직접 읽어 확인하고 비교는 같은 조건에서 수행한다.
답변 근거가 없는 질문과 주요 실패 경로도 확인하며 성능 향상을 미리 약속하지 않는다.

지연은 검색을 포함한 전체 응답과 LLM 호출 시간 등 측정 구간을 명시한다.
추론 실험은 기준선과 한 변경축의 반복 측정·품질 비교를 남긴다. 합성 데이터·가상 시나리오와
실제 사용자 피드백을 구분하고, 임베딩 실험을 생성형 LLM 서빙·분산학습 경험으로 확대하지 않는다.

데모는 로컬 재현으로 시작할 수 있다. 공개 배포·유료 실행·외부 제출은 별도의 구체적 실행 범위다.
데이터·모델 가중치·비밀키·과제 답안을 README와 함께 무조건 공개하지 않는다.
학습자는 실제 수행과 측정한 결과로 이력서·면접 설명을 준비하고, 상세 근거를 외부 레포에 남긴다.
허브의 STATE에는 현재 위치·확인 범위와 해당 근거 링크를 연결한다. 프로젝트 이력 DB나 두 번째 STATE는 만들지 않는다.

## 4. 현재 위치를 전달한다

**허브와 실습을 함께 읽고 쓸 수 있는 세션**에서는 에이전트가 확인된 근거로 STATE를
갱신하고 다시 읽어 확인한다. 다른 작성자의 변경이 있으면 보존한다.

**실습 공간에만 접근할 수 있는 세션**에서는 다음을 짧게 반환한다.

- 수행: 실제 작성·실행한 것과 코드 위치
- 남은 문제: 막힘, 도움받은 범위, 아직 실행하지 않은 것
- 다음: 다음에 할 행동 하나와 강의 위치

이는 전달문이다. 허브 파일을 직접 저장하지 않았다면 저장 완료라고 말하지 않는다.
허브 세션은 전달 내용을 반영하되, 학습자 보고와 직접 확인한 코드·출력을 구분한다.
로컬 작업이 아직 push되지 않았다면 원격에서 같은 결과를 봤다고 쓰지 않는다.
외부 레포에 두 번째 STATE나 동기화 DB를 만들지 않는다.

저장·커밋·push는 각각 실제 확인한 단계만 보고한다.
진도 전달을 위해 공식 과제 답안이나 비공개 데이터를 공개할 필요는 없다.

## 이전 실습을 다시 쓰려면

[보관 색인](../archive/README.md)에서 필요한 코드·결과를 찾는다.
다시 선택한 작업에 필요한 부분만 실습 공간에 가져오고 출처와 기존 도움 범위를 유지한다.
과거 실습 전체를 옮기는 작업을 새 강의 시작의 필수 조건으로 삼지 않는다.
