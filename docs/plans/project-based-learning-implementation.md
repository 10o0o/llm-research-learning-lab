# 프로젝트 중심 학습 계획의 허브 반영 절차

작성일: 2026-10-30 · 상태: 운영 문서 반영 완료 / 설계·적용 기록

[학습 계획](project-based-learning.md)을 실제 허브 문서에 반영하기 위한 다음 작업의 실행 계획이다.
여기서 구현은 학습 운영·안내 문서의 반영을 뜻한다. 학습자가 수행할 프로젝트의 단계와
결과 기준은 학습 계획 3~5절에 있다. 이 문서가 실습 코드를 에이전트에게 일괄 구현시키는 지시는 아니다.
2026-10-30 사용자가 이 계획의 적용과 진도 조정, implementation-final-review를 요청했다.
아래 절차를 기준으로 허브 문서에 반영했다. 실제 학습 수행과 문서 반영을 구분한다.

이번 적용의 범위는 ROADMAP·CURRICULUM·외부 실습 안내·README 보완과 필요한 AGENTS 연결이다.
사용자는 진도 초기화·조정도 허용했지만 새 경로의 첫 구간이 현재 Monitoring 실습과 일치하므로
STATE에는 운영 경로만 연결하고 현재 다음 행동·수행·도움·미완료와 기존 변경을 보존한다.
미정인 프로젝트 데이터·실습 공간·모델·장비는 선택한 것으로 기록하지 않는다.

## 1. 범위 계약

| 항목 | 계약 |
|---|---|
| 필요한 동작 | 현재 강의를 재개하면서 공식 자료와 자기 프로젝트를 연결하고, 학습자 소유권·실제 근거·포트폴리오 목적을 일관되게 안내한다. 후속 작업자가 파일별 변경과 완료 검증을 바로 수행할 수 있어야 한다. |
| 영향 표면 | 저장소 내부 학습 안내와 STATE의 운영 경로 연결. STATE 형식·실제 수행 사실과 공개 API·CLI·환경 설정은 변경하지 않는다. |
| 보존할 경계 | STATE의 실제 선택·다음 행동·미완료·도움 이력과 기존 미커밋 변경, 한 세션의 활성 범위 하나, 공식 과정의 순서·정책, 외부 실습 소유권, CLAUDE.md → AGENTS.md 연결. |
| 포함하지 않는 작업 | 근거 없는 수행·숙달 변경과 자동 진급, 새 수강 결정, 핵심 실습 코드·답안 생성, 외부 레포 변경·재실행, 공통 환경·학습 사이트·진도 DB 신설, 커밋·push·외부 제출·배포·유료 실행. |
| 기존 대안 | 선택한 공식 과정을 그대로 이어갈 수 있다. 자기 프로젝트와 보충 자료의 구체적 선택은 해당 시점에 정한다. 미정 선택 때문에 허브 문서 반영을 중단하지 않는다. |

현재 AGENTS와 학습 세션 스킬은 이미 요청한 학습 방식을 대부분 규정하고 있다.
이를 전면 재작성하거나 별도의 프로젝트 진행 엔진·양식·선택 상태를 추가하지 않는다.

## 2. 기준 위치와 파일별 변경 명세

같은 사실을 모든 문서에 복사하지 않는다. 장기 경로는 ROADMAP, 자료·직접 구간은 CURRICULUM,
공통 도움 규칙은 AGENTS, 외부 연결은 external-practice, 현재 선택·진도는 STATE가 맡는다.

| 파일·기존 위치 | 후속 작업의 구체적 변경 | 완료 조건 |
|---|---|---|
| [ROADMAP](../../ROADMAP.md)의 추천 경로·자료 선택·범위를 넓힐 때 | LLM 응용 → 모델 기반 → 전문화 → 연구의 기존 흐름에 자기 도메인 RAG와 단일 추론 실험을 연결한다. 12주 상대 일정·예상 산출물·범위 축소 조건을 한 곳에 둔다. | 강의 완주가 모든 프로젝트의 선행 조건으로 읽히지 않는다. 추론 실험이 모델 학습 경험을 대체하지 않으며 주차가 진도나 승급 조건이 되지 않는다. |
| [CURRICULUM](../../CURRICULUM.md)의 AX·모델 기반·보충 자료 | Zoomcamp 공식 프로젝트 지침과 적용 구간을 연결한다. 6·7모듈의 선택·구자료 성격을 명시한다. MIT 6.S191은 필요한 부분의 보충 자료로 추가하고 Karpathy·PyTorch와 역할을 구분한다. | 공식 단원·과제와 API·데모·성능 측정 같은 포트폴리오 확장이 구분된다. 새 자료가 STATE의 선택으로 처리되지 않는다. |
| [외부 실습 안내](../external-practice.md)의 실습 공간 선택·실습·진도 전달 | 기존 강의/지속 프로젝트 레포를 재사용하는 경로에 자기 데이터 적용을 연결한다. 외부 README에 남길 문제·데이터·실행법·평가·실패·한계·도움의 최소 근거를 보완한다. | 레포를 단계마다 새로 만들거나 허브에 코드를 넣지 않는다. 상세 근거와 현재 진도의 원본이 분리되고 기존 전달 절차를 재사용한다. |
| [README](../../README.md)의 필요한 문서·주자료 요약 | 계획 문서 탐색 링크를 유지하고 적용 후 문서 상태와 현재 경로 요약을 맞춘다. 상세 일정·과제 기준은 복사하지 않는다. | 시작은 계속 STATE의 실제 다음 행동이다. 새 독자가 계획·현재 운영·현재 진도를 구분할 수 있다. |
| [AGENTS](../../AGENTS.md)의 읽을 범위·설명과 구현 도움 | 기본 유지. 위 문서만으로 표현할 수 없는 실제 행동 충돌이 확인된 경우에만 해당 문장을 최소 수정한다. | 강의·공식 과제 중심, 핵심 구현·실행·첫 해석의 학습자 소유권과 기존 자동 진도 저장이 유지된다. |
| [study-session 스킬](../../.agents/skills/study-session/SKILL.md)의 범위 연결 | 기본 유지. 현재 프로젝트를 선택한 뒤 재개하는 흐름에서 실제 누락이 확인될 때만 기존 안내 절차에 짧게 연결한다. | 커리큘럼 개편을 학습 세션의 역할로 바꾸지 않고, 강의 목록·공통 정책·새 진도 필드를 중복 추가하지 않는다. |
| [STATE](../../STATE.md)의 재개 위치 | 사용자가 허용한 조정 범위에서 채택한 운영 경로를 연결한다. 현재 Monitoring 재개 위치와 다음 행동은 유지한다. | 실제 수행·도움·미완료와 기존 미커밋 내용이 보존되고 새 프로젝트를 시작·완료한 것으로 쓰지 않는다. |
| [공식 과제 정책](../../.agents/references/official-course-policies.md)·보관 자료·검증 스크립트 | 기본 수정 대상에서 제외한다. | 기존 정책·과거 작업을 보존한다. 공식 정책의 실제 변경 등 별도 근거가 생긴 경우에만 해당 범위를 다시 판단한다. |

ROADMAP·CURRICULUM·외부 실습 안내를 중심으로 보완하고, 이미 일치하는 내용은 재작성하지 않는다.
AGENTS·스킬의 조건부 변경은 의무 체크박스가 아니며, 충돌이 없으면 무변경이 완료 상태다.

## 3. 실행 순서

### 단계 1: 현재 작업과 적용 범위 확인

1. 루트 AGENTS, 최신 STATE, 관련 diff와 실제 파일을 읽는다.
2. 작성 당시 STATE에는 기존 미커밋 변경이 있었다. 그 변경을 작업 소유 변경과 구분하고,
   전체 파일을 이전 커밋·이 문서의 스냅샷으로 되돌리거나 새 형식으로 압축하지 않는다.
3. 학습 계획의 사용자 요구와 아직 미선정인 제품·데이터·장비·강의 구간을 구분한다.
4. 이 구현 계획에 따른 허브 반영을 요청받으면 위 범위에서 실행한다. 같은 문서 수정의 승인을
   반복 요청하지 않는다. 실습 선택에 필요한 정보는 해당 실습 착수 전에만 확인한다.

완료 근거: 실제 수정 대상과 보존 대상이 구분되어 있고 현재 다음 행동을 설명할 수 있다.

### 단계 2: 공식 자료와 과제 경계 확인

다음 공식 원문과 선택한 판본을 확인한다. 전체 강의 재조사를 반복하지 않고 반영할 주장에 필요한
직접 구간만 읽는다. 자료를 읽는 것과 수강·실행을 구분한다.

- [Zoomcamp 2026 변경 사항](https://github.com/DataTalksClub/docs/blob/main/courses/llm-zoomcamp/whats-new.md), [Monitoring 4~14강 목차](https://github.com/DataTalksClub/llm-zoomcamp/blob/main/05-monitoring/README.md)
- [프로젝트 원문](https://datatalksclub.github.io/docs/courses/llm-zoomcamp/project/), [AI 사용 정책](https://datatalksclub.github.io/docs/courses/zoomcamp-logistics/ai-usage/), [2026 일정](https://courses.datatalks.club/llm-zoomcamp-2026/)
- [MIT 6.S191 일정·선수조건](https://introtodeeplearning.com/), [Karpathy 목차](https://karpathy.ai/zero-to-hero.html), [PyTorch 기초](https://docs.pytorch.org/tutorials/beginner/basics/intro.html)

완료 근거: 현재 자료에 맞는 직접 링크가 있고, 선택 자료·공식 필수·프로젝트 확장의 구분이 맞는다.
공식 사이트에 없는 수료·AI 도움·답안 공개 조건을 추정해서 추가하지 않는다.

### 단계 3: 경로와 자료 문서 반영

1. ROADMAP에 12주 작업량 가정과 산출물 연결을 반영한다. 날짜를 고정하거나 단계를 자동 진급시키지 않는다.
2. CURRICULUM에서 현재 Zoomcamp 경로를 유지하고 공식 프로젝트·기초 보충·후속 심화의 역할을 명시한다.
3. 보관된 micrograd·makemore와 기존 ONNX 작업을 필요할 때 재사용하도록 기존 보관 색인을 연결한다.
   과거 기록 전체를 필수 재수행 과제로 부활시키지 않는다.
4. 강의에서 제공하는 필수 범위와 취업용 확장의 출처를 나눈다. 초기 평가 문항 수·API·데모·측정은
   제안 기준이며 공식 수료 조건이 아니다. 비용·일정·공개 상태는 확인 날짜와 한계를 둔다.

완료 근거: 주자료 하나를 따라가면서 프로젝트로 적용하는 방법과 후속 범위 선택 시점이 보인다.

### 단계 4: 실습 연결·탐색·조건부 에이전트 안내 반영

1. external-practice에 자기 도메인 적용과 README의 근거를 보완한다. 기존 전달 경로를 재사용하며
   결과 원본·진도 원본을 추가하지 않는다. 학습자에게 별도 양식 작성을 요구하지 않는다.
2. README는 짧은 요약과 링크만 맞춘다. 시작·계속은 기존 STATE의 다음 행동으로 돌아간다.
3. 아래 시나리오에서 실제 충돌이 있으면 AGENTS의 해당 규칙만 보완한다. 스킬 변경이 꼭 필요하면
   skill-creator 지침을 읽고 기존 study-session의 연결 부분만 최소 변경한다.
4. 외부 실습 지침·코드·환경은 이 관리 작업에서 변경하거나 재실행하지 않는다.
   기존 허브 규칙이 외부 세션에 자동 적용되는 것으로 쓰지 않는다.

완료 근거: 큰 흐름 관리와 도움의 역할이 유지되며, 프로젝트 계획이 학습자 대신 구현하는 권한이 되지 않는다.

## 4. 후속 학습 실행의 연결점

운영 문서 반영이 끝나도 새 프로젝트나 강의를 시작한 것으로 처리하지 않는다.
다음 학습 시작에는 최신 STATE에서 이어간다. 현재 위치가 그대로라면 Monitoring 4강이 재개 위치다.
사용자가 선택·수행을 보고하거나 실제 근거가 새로 확인된 경우에만 기존 저장 절차로 STATE를 갱신한다.

| 실습 전환 시점 | 그때 확인할 입력 | 학습자가 수행할 범위와 남길 근거 |
|---|---|---|
| 첫 프로젝트 착수 | 사용자·제품·공개 데이터, 사용할 외부 레포, 공식 프로젝트·공개 정책 | 자기 데이터 ingestion·검색·답변의 첫 버전과 실제 실행. 계획 단계에서 경로·파일을 이미 만든 것으로 쓰지 않는다. |
| 평가·개선 | 기대 근거가 있는 질문, 조정/최종 확인용 구분, 비교할 변경 | 기준선과 후보 결과, 일부 답변 직접 검토, 실패 유형·선택 이유. 에이전트가 첫 해석을 대신 채우지 않는다. |
| API·실행 정리 | 기존 환경·인터페이스, 재현에 필요한 최소 도구 | 실행법과 주요 경로 확인, 지연·비용 측정. 공개 배포·유료 실행은 구체적 범위를 별도로 정한다. |
| 모델 기반·두 번째 실험 | 기존 자기 코드·도움 이력, 필요한 공식 구간, 모델·장비·예산 | 선택 구간을 수행하고 한 변경축의 반복 측정과 품질 비교를 남긴다. GPU 사용 가능성이나 학습 경험을 추정하지 않는다. |

이미 보고·확인된 학습을 새 시험으로 반복하지 않는다. 선택이 필요한 시점에는 가장 맞는 후보와
범위를 제안하고 짧게 확인하며, 매 단계 재승인 절차나 의무 준비도 시험을 만들지 않는다.
실습 상세 계획은 실제 선택·코드·환경을 보고 외부 레포의 기존 문서에 구체화한다.

## 5. 의미와 동작 시나리오 검토

이 표는 안내 문서를 읽어 점검하는 사례다. 학습자 실습을 대신 실행하는 테스트가 아니다.

| 상황 | 기대하는 안내·저장 동작 |
|---|---|
| 문서 반영 후 “계속” | 최신 STATE의 자료·다음 행동으로 복귀한다. 계획의 1주차나 MIT 1강부터 재시작하지 않는다. |

## 6. 최종 검토·검증·인계

1. 작업 소유의 전체 diff와 새 파일을 읽는다. 미선정 사항을 현재 사실로 쓴 곳, 중복 원본,
   불필요한 필수화, 학습자 소유권·미완료·기존 변경 손실이 없는지 점검한다.
2. 실제 안내 규칙이 바뀌었다면 implementation-final-review로 위험에 맞게 독립 검토한다.
   문서 확장자만으로 단순 교정으로 분류하지 않는다. 계획·보고만 작성한 경우에는 구현 완료로 취급하지 않는다.
3. 리뷰 수정 후 관련 시나리오를 다시 확인하고 다음 저장소 필수 검사를 실행한다.

   ```bash
   python3 scripts/check_links.py
   git diff --check
   ```

4. 새 미추적 문서는 `git diff --check`에 포함되지 않을 수 있으므로 별도로 읽고 공백을 확인한다.
   STATE의 변경이 위 범위 안인지, 제외 파일이 작업 전 내용 그대로인지 확인하고 `CLAUDE.md` 연결을 확인한다.
   실행·검증 설정까지 변경했다면 code-change-verification에 따라 해당 동작도 검사한다.
5. 계획 문서의 상태와 README 탐색 문구를 실제 적용 결과에 맞춘다. 적용 후 상세 운영은 기존 기준
   문서에서 관리하고 이 두 계획은 설계 이력으로 남긴다. 모든 계획 문서를 매 세션 읽도록 만들지 않는다.
6. 변경 문서, 검증 결과, 미정인 실습 선택, STATE 보존과 실제 저장 단계를 구분해 보고한다.
   커밋·push·프로젝트 생성·수강·실행이 없으면 이를 완료한 것으로 쓰지 않는다.

내부 링크·공백 검사 통과는 안내의 의미, 실제 튜터 행동, 프로젝트 품질 또는 취업 효과를 입증하지 않는다.
완료 기준은 이 검증과 시나리오 검토가 끝나고, 최신 진도를 유지한 상태에서 다음 학습을 재개할 수 있는 것이다.
