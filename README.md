# LLM Research Engineer Learning Lab

LLM Research Engineer를 목표로 공부하는 가벼운 개인 학습 저장소입니다.
복잡한 진도 관리보다 충분한 설명, 작은 실행, 학습자의 독립 시도와 해석을
우선합니다.

[현재 학습 위치](./STATE.md) · [자세한 사용법](./USAGE.md) ·
[학습 로드맵](./ROADMAP.md) · [보류 자료](./DEFERRED.md) · [역량 참고](./CURRICULUM.md)

## 지식 서재 웹

`knowledge/`의 개념 문서를 홈·검색·분야별 목록·상세 화면으로 읽을 수 있습니다.
Node와 npm을 준비한 뒤 `web/`에서 `npm ci`, `npm run build`,
`npm run preview`를 실행합니다. [실행·검증 방법](./web/README.md)을 참고하세요.
공개 사이트는 [GitHub Pages의 지식 서재](https://10o0o.github.io/llm-research-learning-lab/)입니다.
`main`에 push하면 `public-validation` workflow의 검증을 통과한 뒤 자동으로
배포합니다. 재배포하려면 GitHub 저장소의 **Actions**에서 `public-validation`을
열고 `main`을 선택해 **Run workflow**를 실행합니다. Pull request와 다른 branch는
검증만 실행하며 배포하지 않습니다. 검증이나 배포가 실패하면 실패한 job의 로그를
확인하고 원인을 수정한 뒤 `main`에 push하거나 workflow를 다시 실행합니다.

## 가장 빠른 시작

이 저장소를 작업 공간으로 연 Agent는 [`STATE.md`](./STATE.md)의 현재 범위와
다음 독립 행동을 읽습니다. `STATE.md`는 재개용 북마크일 뿐, 숙달 기록이나
점수표가 아닙니다.

| 요청 | 동작 |
|---|---|
| `오늘 학습 시작` | 현재 주강의 범위에서 연결된 module 하나를 진행 |
| `전체 학습 흐름 시작` 또는 `오늘 전체 학습 흐름 시작` | 승인된 같은 과정·과제 범위에서 module을 이어 가되 다른 과정으로 자동 진입하지 않음 |
| `계속` | `STATE.md`의 다음 독립 행동을 재개 |
| `오늘 학습 종료` | 학습을 멈추고 확인된 재개 위치로 `STATE.md` 갱신 |
| 확인된 챕터 전환 / `$finish-chapter` / `이번 챕터 정리해줘` | 실습 보관·챕터 회고·knowledge 갱신·검증 후 초기화, STATE 갱신·검증 후 로컬 커밋 |

`STATE.md`가 없거나 실제 artifact와 충돌하면 Agent는 다른 운영 상태를
추측하지 않습니다. 확인된 근거로 북마크를 갱신하고 변경을 알립니다.
재개 위치가 불명확하면 필요한 사실만 질문합니다.

## 학습 방식

기본 module은 다음 순서로 진행합니다.

```text
기준 자료·판본 → 직접 링크 → 이번 설명 범위 → 수행할 공식 실습 → 확인할 결과
→ 영상·문서·공식 자료 기반 대화로 학습
→ 공식 구현·exercises·assignments의 직접 수행과 결과 해석
→ 1~2분 무보조 설명과 조건을 바꾼 사례 하나
→ 정답·수정점·빠진 생각을 묶은 한 번의 전체 피드백
```

공식 구현·exercises·assignments가 기본 실습입니다. KANT는 진도·주제 대조용이며
기본 실습이나 완료 기준으로 사용하지 않습니다. 강의 구현은 설명을 따라
작성해도 되며 별도 문제는 직접 시도합니다. 완성 노트북 실행이나 AI 보충
예제로 공식 실습을 대체하지 않습니다. 매 구간마다 새 시험·보고서를 만들지
않고 공식 요구사항에 대한 답·코드·실행·해석을 확인합니다.

주강의의 순서와 자료별 역할은 [학습 로드맵](./ROADMAP.md)을 따릅니다.
학습 시작은 새 준비도 진단이나 로드맵 검토가 아니라 현재 주강의 단원으로
연결합니다. 영상·문서·공식 자료 기반 대화를 허용하며, 설명 매체를 바꾸어도
공식 내용과 실습을 축소하지 않습니다. 확인하지 않은 영상 내용이나 시각을
만들지 않습니다. 현재 설명에 필요한 선수개념을 보강한 뒤 같은 주강의로
돌아갑니다. 핵심 재구성에는 공식 API 문서를 참고해도 됩니다.

오류가 발생했다면 수정 전에 세운 첫 원인 가설과 이를 확인한 방법을
설명합니다. 오류를 일부러 만들거나 이미 이해한 내용을 반복 시험하지 않습니다.

공식 실습 본문은 배치할 때 확인하고, 접근·실행 제약이 있으면 미완료로
남깁니다. 대화형 학습을 영상 시청으로, 로컬 검사 통과를 대학의 공식 채점
통과로 표현하지 않습니다. Optional·Bonus는 선택 항목으로 표시하며 보조
자료를 참고했다고 그 과정 전체의 실습을 추가하지 않습니다.

모듈 끝에는 목적·원리·가정·한계를 자기 말로 설명하고, Tensor 문제에서는
shape와 흐름도 직접 제시합니다. 주간 회상은 지난주 개념 2개와 더 이전 개념
1개를 예고 없이 묶어 확인합니다. knowledge는 학습자의 무보조 초안 이후에만
교정하며, 코드 재구현은 로드맵의 대표 단위에 집중합니다. 전체 과제를 다시
작성하는 의무는 없습니다. 공식 과제 수행과 무보조 재구현은 별개의 근거입니다.

경로는 기초 → ML → DL → NLP → LLM Systems → 독립 실험·면접 순서입니다.
52주 중 48개 실효 학습주 × 주 60시간 = 2,880시간은 초기 예산이며, 핵심
학습의 깊이가 부족하면 일정을 늘립니다. Kaggle은 P1만 필수이고 P0·P2·P3는
선택입니다. 과정별 판본·범위·예산은 [ROADMAP.md](./ROADMAP.md), 기초부터
시스템까지의 정적인 설명 기준은 [CURRICULUM.md](./CURRICULUM.md)를 따릅니다.

MIT 18.05 문제 세트와 CS229·CS231n·CS224N·CS336 공식 과제의 written·코드·
노트북·저장 출력 답안은 별도 비공개 작업 공간에 둡니다. 공식 문제 원문과
저작권 자료도 공개 저장소에 넣지 않습니다. 자신의 개념 노트와 공식 답안과
분리된 빈 파일 재구현, 공개 가능한 대회 작업·재현 보고서는 남길 수 있습니다.

## CS224N의 수행 범위와 도움

CS224N Spring 2024 A1~A4는 `P3`에서 written·수학·프로그래밍 요구사항까지
전부 수행합니다. [공식 AI 정책](https://web.stanford.edu/class/archive/cs/cs224n/cs224n.1246/index.html)은
AI 협업을 허용하지만 직접 답 요구·복사와 AI의 실질적 과제 대행을 금지합니다.
개별 과제의 별도 지침도 확인합니다.

파이널 프로젝트만 보류이며 `P5`의 추론 최적화 프로젝트가 대신합니다.
완료가 아니라 미완료 보류이고 복귀 조건은 [`DEFERRED.md`](./DEFERRED.md)에
있습니다. 변경·생략은 사용자 결정으로만 합니다.


## CS336의 엄격한 AI 경계

[CS336 Assignment 1 공식 AI 지침](https://github.com/stanford-cs336/assignment1-basics/blob/a158843b20107949f1a8d7df1b05cd33b9166712/AGENTS.md)을
따릅니다.

- 학습자가 과제 코드를 직접 작성하고 제공된 테스트를 실행합니다.
- AI는 개념 설명, 오류 메시지 해석, sanity check와 일반적인 review만
  제공합니다.
- 학습자가 모든 bash command를 직접 실행하며, AI는 assignment repo에서
  command를 실행하지 않습니다.
- AI는 공식 handout에 이미 나온 command의 의미와 학습자가 제공한 실행
  결과는 설명할 수 있지만, 과제 해결·자동화를 위한 새로운 command
  sequence는 만들지 않습니다.
- 명시적으로 요청해도 AI는 과제 코드, pseudocode, patch, TODO 해답을
  제공하지 않습니다.

기초 실습은 learning-lab의 Python 3.14 환경에서 실행합니다. 실제 과제는
별도 sibling clone과 Python 3.12 또는 3.13의 독립 uv 환경을 사용하며,
과제 dependency를 learning-lab이나 현재 `.venv`에 합치지 않습니다.

CS336 복귀는 로드맵의 구현·실행·해석 근거로 제안합니다. 기존 작업을
보존하며, 사용자 승인 없이 현재 과정을 바꾸지 않습니다.

## 파일 변경과 저장

Agent는 확인된 재개 위치가 바뀌면 `STATE.md`를 사전 승인 없이 갱신합니다.
아래 챕터 전환 마무리 외의 일반 학습에서는 다음 작업을 자동으로 하지 않습니다.

- TIL 또는 knowledge 갱신
- 새 practice artifact 생성
- 다음 강의나 source 자동 선택·등록
- commit 또는 push

`STATE.md`는 학습자의 설명과 확인한 파일을 근거로 갱신하고 변경을 알립니다.
이 권한은 새 과정 진입이나 학습 순서 변경을 허용하지 않습니다.
일반 작업의 commit과 push는 각각 별도의 명시적 요청이 필요합니다.
확인된 챕터 전환의 기본 마무리와 명시적 마무리 요청은 아래 범위의 로컬 commit까지 포함하는 예외입니다.

날짜별 기록이 필요하면 `오늘 TIL 저장해줘` 또는 `$save-today-til`을,
재사용할 개념 노트가 필요하면 `$update-learning-knowledge`를 명시적으로
호출합니다. 두 도구 모두 현재 대화나 사용자가 정확히 지정한 artifact만
사용하며, 자동 commit이나 push를 수행하지 않습니다.

실제 챕터 전환이 확인되면 다음 챕터를 시작하기 전에
[`$finish-chapter`](./.agents/skills/finish-chapter/SKILL.md)를 기본으로 수행합니다.
별도 마무리 요청이나 재승인을 요구하지 않으며, 명시적으로 호출할 수도 있습니다. 저장된 노트북을 그대로 보관하고, 옆의 챕터 회고에 과정·도움·
결과·한계를 정리하며, 재사용할 개념은 knowledge에 반영합니다. 보관 검증과
문서 검사, 학습자의 knowledge 초안 확인과 교정이 끝나면 `main.ipynb`와
해당 챕터의 `recall.ipynb` 같은 작업 노트북을 초기화합니다. 대화에서 학습자가
직접 작성한 개념 설명도 초안으로 사용하며 중복 작성을 요구하지 않습니다.
학습자 근거가 없는 개념은 회고의 미확인 사항으로 남깁니다.
STATE를 갱신한 뒤
해당 학습 변경을 검사하고 로컬 커밋까지 수행합니다. push는 하지 않습니다.
`완료`나 `오늘 학습 종료`만으로는 이 작업을 시작하지 않습니다.

## 저장소 구조

| 위치 | 용도 |

| [`STATE.md`](./STATE.md) | 공개 가능한 현재 범위와 다음 독립 행동 |

| [`DEFERRED.md`](./DEFERRED.md) | 이번 경로에서 뺀 자료와 복귀 조건 |
| [`CURRICULUM.md`](./CURRICULUM.md) | 역량과 기존 자료 범위 참고 |
| [`archive/`](./archive/) | 수정하지 않고 보존하는 과거 기록 |

공개 문서에는 비공개 답변 전사, private 경로, 내부 ID·hash를 기록하지
않습니다. STATE에는 세션 이력이나 평가 수치를 넣지 않습니다. 공개 가능한
실험 결과와 학습 과정은 실습·챕터 회고에 출처와 한계를 구분해 남깁니다.
실행하지 않은 결과를 꾸며 쓰지 않습니다.
