위에서부터 1로 센다. 원본을 고치거나 전체 실행하지 않았다. 현재 대화의

숙달을 확인했다고 기록하지 않는다.

## 과정과 확인 결과

### 입력과 정답 확률

`emma`의 bigram 입력 ID는 `[0, 5, 13, 13, 1]`, 정답 ID는
`[5, 13, 13, 1, 0]`이다. 학습자는 한 칸 뒤 문자가 정답이라는 관계를 설명했다.
확률의 의미가 막혔을 때, 입력 문자로 다음 후보 분포를 만들고 실제 다음 문자의
확률을 평가하는 흐름을 대화와 코드로 연결했다.

학습자는 NLL이 백분율이 아닌 벌점이며 정답 확률이 커지면 작아진다고 답했다.
자연로그의 실제 값과 `-log(1/3)`의 계산은 AI 설명으로 보완했다.

### train으로 만들고 dev/test에서 평가

이름 32,033개를 25,626 / 3,203 / 3,204개로 나누었다. 두 train 빈도표의
총 전이 수는 모두 182,625다. 전체 데이터 표 대신 train에서 새 표를 만들었다.

| 데이터 | bigram NLL, add-one | trigram NLL, add-one |
|---|---:|---:|
| train | 2.4544 | 2.2157 |
| dev | 2.4533 | 2.2365 |
| test | 2.4584 | 2.2373 |

셀 30의 저장 결과다. 이번 이름 분할에서 trigram 벌점이 더 낮았으며,
모든 데이터나 모델에서의 우열을 확인한 것은 아니다.

### Smoothing 선택

| alpha | train NLL | dev NLL |
|---:|---:|---:|
| 0.01 | 2.1835 | 2.2318 |
| 0.1 | 2.1877 | 2.2225 |
| 1 | 2.2157 | 2.2365 |
| 10 | 2.3563 | 2.3637 |
| 100 | 2.7453 | 2.7464 |

셀 31에 저장된 비교이며 현재 대화에서도 확인했다. 학습자는 train 최솟값
대신 dev 값을 보고 선택해야 한다고 답했다. 후보 중 dev가 가장 낮은
`alpha=0.1`로 표를 다시 만든 셀 32의 test NLL은 `2.2240`이다.

처음 비교 코드는 dev/test를 출력했다. 수정 전 test 값을 이미 본 사실은
현재 대화에 남아 있다. 최종 표만 보고 test를 마지막에 처음 한 번 조회한
실험으로 해석해서는 안 된다.

### 행 인덱싱과 안정적인 손실

- 셀 33: `W_all[all_xs]`의 shape은 `(228146, 27)`이며, one-hot 행렬곱과
  비교는 `True`였다. 인덱싱 문법과 입력 ID 생성은 도움을 받았다.
- 셀 34: 인덱싱으로 학습·역전파·최종 평가를 수행했다.
- 셀 35: 수동 NLL과 cross-entropy가 모두 `2.4611148834228516`으로 같았다.
  현재 가중치로 새로 재계산한 결과가 아니라 당시 비교다.
- 셀 36: logits `[[1000, 1000, 1000]]`, 정답 `[2]`에서 수동 계산은 `nan`,
  cross-entropy는 `1.0986123`이었다. 학습자는 큰 logits도 안정적인
  log-softmax 계산을 이용하기 위해 logits를 전달한다고 설명했다.
- 셀 37: cross-entropy 학습의 마지막 저장 NLL은 `2.4605469703674316`이다.
  누적 추가 학습이므로 최초 100회 결과나 함수 변경 자체의 성능 향상이 아니다.

### Sampling과 greedy

| 선택 방식 | 출력 | 종료 |
|---|---|---|
| sampling | `cexze`, `momasurailezityha`, `konimittain`, `llayn`, `ka` | 모두 종료 문자 도달 |
| greedy | `a` 다섯 번 | 모두 종료 문자 도달 |

이름마다 입력 ID·목록·종료 여부를 초기화하고 최대 30번 선택했다.
현재 greedy 경로는 `. → a → .`다. 학습자는 greedy는 난수 대신 최대 확률을
선택하므로 seed를 바꿔도 같다고 설명했다. 다섯 출력의 관찰이며 sampling이
항상 서로 다른 이름을 만든다고 일반화하지 않는다.

### 수정하면서 만난 문제

아래는 현재 대화에서 확인·수정한 과정이다. 모두 보관본에 오류 출력으로 남아
있는 것은 아니다. 학습자가 말하지 않은 첫 오류 가설이나 검증 과정은 만들지 않았다.

- `words.copy`에 괄호가 없어 리스트 대신 함수를 shuffle에 전달했다.
- 슬라이스 끝 제외 규칙과 test의 접미 구간을 혼동했다.
- trigram용 시작점 사이 `. → .`를 bigram에 추가해 이름 수만큼 과집계했다.
- 확률표 인덱스에 문자열을 넣었다가 `stoi`로 변환했다.
- `(1, 3)` 확률표의 `probs[2]`는 세 번째 행이라는 점을 확인했다.
  학습자는 정답을 하드코딩하지 않고 `target`을 사용해야 한다고 지적했다.
- 생성 목록을 이름마다 초기화하지 않아 다섯 이름이 이어 붙었다.

## 보관본의 한계와 다시 볼 부분

- 셀 22에 `if ix == 0:` 뒤 백틱 두 개가 있어 문법 오류가 난다. 기존 출력은
  현재 소스 실행의 증거가 아니다. 셀 38~39에는 별도의 생성 구현·결과가 있다.
- 셀 17·22·31·35·37은 출력이 있으나 execution count가 비어 있다. 일부 결과는
  대화에서 확인했지만, 저장 파일만으로 실행 순서·커널 상태를 복원할 수 없다.
- 셀 21·34·37은 같은 `W_all`을 반복 업데이트한다. 새 커널에서 순서대로
  실행하면 저장 수치가 재현된다는 보장은 없다. 전체 재실행은 미검증이다.
- E02/E03 counting 모델은 train 전용이다. E04/E05 신경망 실습은 전체 이름의
  `all_xs/all_ys`를 쓴다. 두 평가 조건을 섞지 않는다.
- 대화형 학습과 공식 구현 참조로 진행했다. 영상 시청 여부·재생 위치는 미확인이다.
- 인덱싱과 반복문 구성은 후속 공식 실습에서 다시 적용한다. 챕터 전체를
  암기해 재작성하는 추가 시험을 요구하지 않는다.
