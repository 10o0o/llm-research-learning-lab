# fast.ai 책 2장: 곰 분류기에서 실제 사용까지

정리일: 2026-09-22. 기준은 fast.ai 2022 Part 1 Lesson 2와 fastbook 2장
From Model to Production이다. 사용자가 남은 항목을 미완료로 두고 다음 학습으로
이동하기로 결정했다. 전체 과정 완료·독립 회상 통과·공개 배포 성공을 뜻하지 않는다.

## 보존과 수행 범위

책 원문·공식 구현·사진·학습자 실행 출력이 섞인 노트북은 비공개 챕터 보관 영역의
`fastai-book02-production.ipynb`에 바이트 그대로 보존했다. 공개 Git에는 회고와
학습자 설명에 근거한 개념 노트만 넣는다. 읽기용 `02_production.ipynb`와 최초
원본은 유지한다. 루트 main·recall은 이미 빈 코드 셀이므로 중복 보관·초기화하지
않았다. 커널, 데이터와 export.pkl도 변경하지 않았다.

완성된 공식 노트북을 로컬 환경에 맞춰 실행한 실습이다. 독립 구현으로 기록하지
않는다. AI가 전용 uv 환경·검색 호환 코드·한국어 요약을 준비했고 학습자가 실행했다.
영어 원문을 유지한 요약·해설이며 전체 번역이 아니다. 영상 전체 시청은 확인하지 않았다.

## 저장 결과

셀 번호는 보관본 기준 1부터 센다. 노트북을 재실행하지 않았다.

| 학습 | 셀 97: ResNet18 fine_tune(4), 마지막 train loss 0.790967, valid loss 0.096638, error_rate 0.055556 | 작은 검증 집합의 관측값; 일반 성능 보장 아님 |

학습 표의 초기 단계와 추가 4 epoch 합계는 약 20초다. 표만으로 실제 학습
장치나 현재 커널의 가중치를 확정하지 않는다. 보관본의 나머지 오래된 출력은
학습자 실행 증거로 일괄 간주하지 않는다.

## 장애와 도움

VS Code에서 Cleaner 메뉴와 업로드 위젯이 동작하지 않았다. Python 셀의 성공과
별개로 Jupyter 로그에 위젯 모듈 로딩 및 CDN 접근 실패가 관찰됐다. AI가 폴더별
번호 사진과 정적 HTML을 만들고 Windows 다운로드 폴더에 복사해 사진을 확인하도록
도왔다. 이 자료는 현재 커널의 Train/Val 구분이나 loss 순서를 재현하지 않는다.

학습자는 black·grizzly에서 수정 후보가 없다고 보고했다. teddy-15를 개로 의심했으나
원본 확대 검토에서 곰 인형으로 판단했다. 확정된 라벨 변경·삭제는 없었다.
모델이 틀렸다는 이유로 정확히 라벨된 실제 환경의 사진을 제외하지 않는다고 설명했다.

## 학습자 설명과 knowledge 반영

대화의 학습자 답변을 초안으로 사용했다. 해설 직후 답변도 있으므로 지연된
무보조 회상 전체 성공으로 보지 않는다.

- parent_label이 상위 폴더에서 정답을 얻고 valid_pct가 검증 비율을 정한다고 설명했다.
  모든 파일이 images 폴더에 있다면 CSV에서 대응 라벨을 찾아야 한다는 조건 변경도 설명했다.
- crop으로 중요한 특징이 잘리거나 곰이 사라질 수 있다고 설명했다.
- 정답이 올바른 어려운 사진은 유지하고 별도의 학습 데이터를 보강해야 한다고 제안했다.
  야간·어두운 환경·겨울의 평가 데이터 필요성을 설명했다.
- 추론에서는 가중치가 갱신되지 않으며, 학습에서 바뀐다고 설명했다.
  저장에 모델 구조·학습한 파라미터가 필요하고 학습용 증강을 그대로 적용할 필요는
  없다고 답했다. 처리 설정·클래스 정보까지 포함한다는 부분은 튜터가 보완했다.
- 원래 살 가능성이 높은 상품의 구매를 전부 추천의 효과로 볼 수 없다는 방향을 설명했다.

## 해설로 보완했고 독립 설명은 남은 부분

- 전체 학습·검증·저장·추론 흐름의 회상에서 검증을 라벨링과 혼동했고 기울기와
  갱신 과정이 빠졌다. 이후 갱신 시점은 바로잡았지만 전체 흐름의 독립 설명 통과는 아니다.
- item_tfms·batch_tfms의 적용 단위는 맞혔으나, 크기가 달라 배치로 묶기 전에
  실패한다는 이유는 해설로 보완했다.
- 상품 ID와 수량의 구분에서 열의 역할이 뒤바뀐다는 오해를 교정했다.
- Drivetrain의 네 단계 전체는 회상하지 못했다. 단계 순서는 튜터가 다시 설명했다.
- 야간 학습 데이터가 전혀 없다고 오류만으로 확정할 수 없다는 점,
  out-of-domain·domain shift 구분, 조건별 점수·누락 경고 관측은 해설로 보완했다.
- 단계적 도입에서 감독 범위를 자동으로 줄이지 않는 이유, CPU/GPU의 조건부 선택,
  서버·기기 배포, 텍스트 생성의 정확성 한계는 설명했으나 모두 독립 확인한 것은 아니다.
- 전체 혼동 행렬 해석, seed와 입력 목록의 관계, 저장된 전처리 설정은 해설을 포함한다.

## 남기는 미완료

실제 업로드·버튼 동작과 웹 공개 배포, 데이터 수정 후 재학습·성능 비교,
Questionnaire 전체의 독립 답변, Further Research 및 별도 블로그 작성은 미완료다.
UI와 공개 배포가 없는 상태를 공식 문항 9 전체 수행으로 기록하지 않는다.
새 커널에서의 전체 재현과 배포 환경에서의 지연 측정도 미검증이다.
사용자의 전환 결정은 이 장의 남은 작업을 보류하는 것이며 다음 과정의 필수 범위를
생략하는 권한으로 확대하지 않는다. P0는 계속 진행 중이다.
