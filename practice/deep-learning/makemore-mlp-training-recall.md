# MLP 학습·평가 흐름 재구현

- [원본 보관본](./makemore-mlp-training-recall.ipynb)

  학습 흐름과 E03의 직접 연결 실험. 공식 exercise 자체와 구분되는 재구현이다.

## 범위와 지원

데이터 준비·모델 정의는 다시 작성할 필요가 없다는 범위를 정한 뒤,
학습자 요청으로 AI가 이 부분을 `recall.ipynb`에 세팅했다(셀 2~5).
학습·평가 함수는 학습자가 빈 셀에 작성했다(셀 7). 셀 번호는 1부터 센다.

작성 중 `torch.randint`의 인자 이름을 `batch_size`로 적어 편집기 오류가
나타났다. AI가 `size`라는 API 이름과 값으로 전달하는 변수의 차이를 설명했다.
알고리즘 본체는 학습자가 작성했지만 준비 코드와 API 보조가 있었으므로
전체 시도를 완전 무보조 성공으로 기록하지 않는다.

## 저장된 실행과 해석

셀 8은 초기 평가, 셀 9는 lr 0.03·1,000회 학습 호출,
셀 10은 학습 후 평가다. 모델은 직접 연결을 포함하고 파라미터는 12,707개다.

| 시점 | train loss | dev loss |
|---|---:|---:|
| 학습 전 | 3.348036527633667 | 3.348778486251831 |
| 학습 후 | 2.4138410091400146 | 2.4144763946533203 |

학습자는 손실 감소를 예측 개선으로 해석했고, 입력과 정답의 행 번호를 따로
뽑으면 엉뚱한 정답이 매칭된다고 설명했다. Dev도 함께 감소했으므로 해당
검증 데이터에서의 개선은 관찰됐으나 모든 데이터에 대한 성능 보장은 아니다.

## 한계와 보관 경계

- 이 재구현은 모델 전체나 데이터 파이프라인의 독립 작성 증거가 아니다.
- 준비 셀은 CPU fallback이 있지만 학습 함수는 장치를 `"cuda"`로 고정했다.
  실제 저장 출력은 CUDA다. CPU에서 그대로 실행할 수 있다고 검증하지 않았다.
- 평가 함수는 데이터를 한 번에 처리하며 더 큰 데이터에서의 메모리 사용은
  별도 검증하지 않았다. Test는 튜닝에 사용하지 않았다.
- 보관 과정에서는 코드를 수정·실행하지 않았다. 초기화된 원본 작업 파일은
  저장 파일만 비우며 열린 편집기 버퍼나 실행 중 커널 상태를 없애지는 않는다.
